2026-09-07 커맨더 학습 정체 점검

후속 구현과 검증 결과는 [학습 관측 및 재개 설정 개선](JW2_COMMANDER_CONTEXT_IMPROVEMENT_20260907.md)에 기록했다. 아래 내용과 코드 위치는 개선 전 점검 시점을 기준으로 한다.

관측 보완만으로 경기 성능이 높아지지 않아 [후속 재점검과 대조 실험](JW2_COMMANDER_CONTEXT_RECOVERY_20260907.md)을 진행했다. 해당 기록에는 원래 학습 자료·Adam 복원, 모델 버전과 독립적인 정책 난수, 보상 할인 및 GAE 대조의 실제 경기 결과를 정리했다.

학습 갱신은 실행되고 있지만 승률 개선으로 이어지지 않는다. 우선 점검할 대상은 **교사가 사용하는 정보와 모델 입력의 불일치**, 그리고 **장기 전략의 결과를 평가하는 critic·advantage**다. 단순 학습 연장·학습률 축소·KL 제거는 이미 시도됐으므로 같은 설정을 다시 돌리는 것을 첫 개선안으로 삼지 않는다. 아래의 코드상 문제와 실험 가설은 구분한다.

**현재 상태와 수치**

`ppo_sustained_search_r2`의 완료된 24개 체크포인트를 다시 읽어 **1,152경기·1,260,828결정**을 확인했다. 해당 실행은 `assessed_waiting_for_analysis`로 끝났다. 점검 중 실제 실행 프로세스는 `cohesion_gather_melee_candidate/run_game_validation.py`이며 교사·실행기 후보를 검증 중이었다. 이것은 새 PPO 갱신이 아니다.

| R2 연속 학습 | 고정 argmax, 48조건 | 샘플링, 48경기 |
|---|---:|---:|
| 출발 PPO version 8 | 43승 | 33승 |
| 추가 8회 | 36승 | 32승 |
| 추가 16회 | 33승 | 34승 |
| 추가 24회, version 32 | 40승 | 30승 |

각 평가의 유효 경기 수는 48, 무효는 0이다. 샘플링은 모델 version에 따라 정책 RNG 초기 상태도 달라지므로 작은 승수 차이를 통계적으로 확정된 효과로 해석하지 않는다. 고정 평가는 해당 48조건의 결과다. 다른 실행 파일·가중치의 성적을 합산한 최고 승률을 만들지 않았다.

마지막 저장 정책의 전체 코호트 점검은 KL **0.00700**, clip 비율 **8.80%**, PPO surrogate **+0.01423**, value loss **0.002061→0.001659**다. 학습 계산이 멎거나 optimizer가 작동하지 않는 문제가 아니라, 개선된 학습 목적값이 실제 게임 성능을 충분히 반영하지 못하는 상황이다. 이번 재검산은 61개 소스·메타데이터·가중치 해시를 확인했다. [재현 스크립트](../debug_artifacts/commander/learning_plateau_audit_20260907/summarize_evidence.py)와 [근거 JSON](../debug_artifacts/commander/learning_plateau_audit_20260907/evidence.json)을 보존했다. 게임과 gradient를 새로 실행한 검증은 아니다.

**1. 우선 개선: 모델에 없는 재편성 이력을 교사는 사용한다 — 입력 누락 확인**

`ranker_ai_commander.cpp:990,995,997,1024`의 교사는 `last_transfer_frame[0..3]`으로 재편성 440프레임 대기, 정찰·복귀 1,100프레임 및 변형별 습격 주기를 판단한다. 실행기는 실제 병력을 옮길 때 이 시각을 갱신한다(`1218`). 하지만 `BuildCommanderView`에는 이 네 값이 없고 관측 마지막에는 직전 행동과 직전 결정 이후 시간만 들어간다(`882`). Python 모델은 과거 상태를 유지하지 않는 feedforward 모델이다(`ranker_commander_model.py:66`).

따라서 모델이 받는 관측·합법 행동 마스크가 같아도 교사 정답은 과거 재편성 시각에 따라 달라질 수 있다. 직전 행동 하나는 여러 결정 전의 이동 시각을 대신하지 못한다. 다만 실제 데이터에서 이러한 충돌이 얼마나 자주 발생하고 승률에 얼마나 영향을 미치는지는 아직 측정하지 않았다.

개선안은 네 이동의 경과시간과 초기 미실행 상태를 명시적으로 관측하는 것이다. 기존 RLO의 **실제 수행 행동** H1 `38..41`과 프레임에서 이력을 복원해 오프라인 BC 후보부터 비교한다. DAgger의 교사 라벨은 실제 행동 이력이 아니므로 복원에 쓰면 안 된다. 마스크 위반·중간부터 시작한 기록은 별도로 처리해야 한다. 경기 단위로 고정한 검증 자료에서 이동 행동별 precision/recall과 연속 역전 오류를 비교한다. 실제 적용에는 C++/Python 관측 크기·스키마·가중치 형식·정밀도 일치 검증을 함께 바꾸는 별도 작업이 필요하다. 기존 528차원 가중치에 새 입력을 조용히 덮어넣지 않는다.

**2. 교사 전략 혼합을 조건 없이 모방한다 — 실제 학습 자료에서 확인**

`CommanderTeacherVariant`는 초반 병력 수, 타워·확장 시점, 공격 전력비, 습격 주기, 목표 우선순위를 바꾼다(`ranker_ai_commander.cpp:919–934`). 이 전략 값 역시 actor 입력에 없다. 기준 BC 수집 설정은 `teacher_variants=15`였고, 현재 BC DAgger2에는 그 교사 자료 **360경기·508,798결정**과 DAgger **332,312결정**이 들어 있다.

서로 다른 전략을 섞는 것 자체가 결함은 아니다. 그러나 관측되지 않는 전략에 따른 서로 다른 정답을 하나의 정책으로 모방하면 argmax 행동과 긴 행동 순서의 일관성이 약해질 가능성이 있다. 이 가능성을 데이터 양 부족과 구분해야 한다.

개선안은 먼저 관측 가능한 상태와 행동 이력만으로 설명되지 않는 라벨 충돌을 집계하고, **기본 교사 자료만 사용한 BC**와 **교사 전략을 명시적으로 조건화한 BC**를 대조하는 것이다. 표본 수·종족·시작 조건·학습 예산 차이를 맞추고 경기 단위 검증을 고정한다. 기본 교사 자체도 전승하지 못하므로 단일 교사만 모방하면 최종 성능 문제가 모두 풀린다는 뜻은 아니다.

**3. PPO의 장기 결과 전달을 검증할 필요가 있다 — 유력 가설, 미입증**

`ranker_commander_rollout.py:297–314`의 기본값은 32프레임당 γ=0.997, GAE λ=0.95이며 `build_batch`는 이를 설정으로 전달하지 않는다. 과거 TD 오차에 대한 `(γλ)^(Δframe/32)`의 1/e 길이는 약 **589프레임**이다. 이는 전체 정책의 기억 길이가 아니라 GAE가 더 먼 TD 오차를 직접 가중하는 길이다. 수천 프레임 뒤에 효과가 나는 확장·생산은 critic의 예측에 크게 의존한다.

마지막 수집 코호트의 0–4,000프레임에서 MC return에 대한 explained variance는 **0.243**이고, 패배 경기에서는 **−0.021**이다. 반면 패배 경기의 GAE target explained variance는 **0.972**다. 이미 자기 예측을 포함한 target에 잘 맞는 것과 장기 결과를 잘 예측하는 것은 구분해야 한다. 손실값 감소만으로 이 문제를 해결했다고 볼 수 없다. MC 역시 실현된 한 궤적의 결과이며 완전한 기대가치 정답은 아니다.

개선안은 γ·λ·critic target 구성을 명시적으로 설정·저장하도록 준비하고, 같은 출발 가중치·Adam·첫 코호트에서 **λ만 바꾸는 짧은 대조**부터 수행하는 것이다. 예를 들어 0.95 대 0.98을 후보로 두되 검증 전 기본값을 교체하지 않는다. γ·보상·entropy·KL까지 한꺼번에 바꾸지 않는다. 이후 각 정책이 수집한 새 코호트에서 결과를 이어가고 최종 판단은 실제 경기 승률·종족별 성적·절단 이유로 한다. 기존 rollout의 재계산만으로 PPO 성능 향상을 주장하지 않는다.

**4. 기존 실행기 공성 문제는 진행 중인 검증을 활용한다**

공유 소스의 교사는 MAIN이 알려진 건물 640px 이내에 접근하면 지상 원거리 지원이 없어도 SIEGE를 고른다(`ranker_ai_commander.cpp:1112`). 근접 유닛의 SIEGE 위치는 목표 앞 128px다(`1536–1537`). 해당 문제를 수정하는 `cohesion_gather_melee_candidate`가 이미 존재하고 실제 경기를 검증 중이다. 같은 후보를 다시 만들거나 병렬로 새 게임을 시작할 필요는 없다. 완료 결과에서 집중 실패 사례와 전체 교사 성적을 함께 확인한 후 다음 BC 데이터 생성의 실행기를 고정하는 것이 순서다. 이 점검에서는 후보 채택이나 승률 개선을 선언하지 않았다.

**5. 일반 CLI 학습 재개 시 설정이 바뀔 수 있다 — 별도 재현·수정 후보**

현재 `ranker_commander_train.py:615–616,660–668`은 PPO 재개 시 학습률은 저장 설정에서 복원하지만 curriculum, 교사 KL initial/floor/decay, critic warmup은 다시 인자를 주지 않으면 CLI 기본값으로 돌아간다. 예를 들어 C2·KL floor 0.01/100회 감쇠를 저장한 정책도 일반 CLI로 재개하면 C0·floor 0/30회 감쇠가 될 수 있다. 명시적으로 입력한 0은 저장값으로 덮지 않아야 한다.

이번 24회 실행은 별도 컨트롤러가 C2·KL 0.05/0.01/100·warmup 1을 명시했고 24개 메타데이터에서도 유지돼, **이 결함이 현재 정체의 원인은 아니다**. 향후 재개를 위한 수정 후보를 [별도 폴더](../debug_artifacts/commander/learning_plateau_audit_20260907/resume_candidate)에 준비했다. 진행 중인 게임 검증이 공유 소스 해시를 고정하고 있어 공용 트레이너 파일에 패치를 적용하지 않았다. 후보의 관련 회귀 결과와 적용용 patch는 같은 폴더에 보존한다.

원래 코드에서 두 테스트의 다섯 assertion 실패로 설정 유실을 재현했고, 후보는 **관련 테스트 5개 모두 통과**했다. 실제 체크포인트 입출력과 CLI 설정 전이를 검사하되 게임 수집·최적화는 모킹했다. 명시적인 0 우선, 기존 PPO 설정 복원, 신규·레거시 기본값 유지가 검증 범위다. [패치](../debug_artifacts/commander/learning_plateau_audit_20260907/resume_candidate/resume_settings.patch)는 미적용 상태이며, [검증 결과](../debug_artifacts/commander/learning_plateau_audit_20260907/resume_candidate/test_results.json)에 원본 실패와 후보 통과를 모두 보존했다. 게임 승률 검증을 대신하는 테스트는 아니다.

**진단·실험 관리에서 함께 고칠 점**

- `build_batch`의 shaping 지배 여부 검사(`303–309`)는 PBRS의 부호 있는 할인합을 먼저 합산하고 절댓값을 취한다. 종료 포텐셜을 0으로 만들면 이 합은 초기 포텐셜의 음수로 상쇄되므로, 초기 포텐셜이 거의 0인 현재 자료에서는 중간 shaping 신호가 커도 거의 0이 나온다. 마지막 기록의 `4.3e-7`을 shaping 신호가 없다는 증거로 쓰면 안 된다. 상쇄 확인 지표와 항별 절댓값·TD/advantage 기여 진단을 분리하고, 보상 배율 자동 변경 규칙은 별도 검증한다.
- PPO는 현재 고정 3에폭이며 내부 KL 조기 중단 설정이 없다. 최대 변화량·최종 전체 코호트 KL을 기록하고 target-KL 조기 중단을 선택 사항으로 넣는 것은 유용한 통제다. 다만 최근 최종 KL 수치만으로 큰 업데이트가 정체의 주원인이라고 할 수는 없다. PPO clipping이 정책 변화량의 절대 한계를 보장하지 않는다는 점과 KL 조기 중단의 사용 예는 [OpenAI Spinning Up](https://spinningup.openai.com/en/latest/algorithms/ppo.html)에 설명돼 있다.
- 평가용 sampling seed를 모델 version과 분리하면 같은 초기 정책 난수 스트림으로 비교할 수 있다. 실제 버전·해시는 계속 기록한다. 합법 행동 수에 따라 RNG 소비량이 달라지므로 그 이후 모든 결정의 난수까지 정렬된다고 주장해서는 안 된다.
- 이전 실험은 no-KL, 작은 학습률, 균형 48조건, 약한 KL, 추가 DAgger, teacher replay 가중치 증가를 이미 시도했다. 공유 gradient 두 코호트의 critic/PPO 크기 비율은 5.6%·10.0%였고 강한 반대 방향도 아니었다. BC anchor가 항상 NONE을 강화한다는 근거도 없다. 따라서 critic 분리·anchor 교체·데이터 증량을 검증 없이 해결책으로 고정하지 않는다.

**권장 순서:** 진행 중인 실행기 검증 완료와 기준 실행기 고정 → 재편성 이력·교사 전략의 관측 가능성 점검 및 오프라인 BC 대조 → 동일 출발점에서 GAE/critic의 한 변수 대조 → 새로운 경기 성적으로 채택 판단. 원본 게임·배포 실행 파일·기존 가중치·진행 중인 검증은 이번 점검에서 변경하거나 재시작하지 않았다.
