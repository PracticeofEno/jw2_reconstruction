## 다시 확인한 원인

1. 기존 BC는 희귀 매크로와 부대 명령의 가중치를 8개 헤드 로그확률 합 전체에 곱했다. v12 자료에서 NOOP는 85.1%이지만 가중 손실 비중은 19.4%였다. 스킬 메뉴 슬롯은 특정 능력의 고정 클래스가 아닌데 슬롯별 빈도 가중치도 적용되어, 자료 0.9%인 스킬이 손실 18.0%를 차지했다. 전역 가중치 조절만으로 생산과 부대 운용을 동시에 교정하기 어려웠다.
2. 원거리 부대의 접근 반응은 근접 유닛에만 적용되어, HOLD 위치의 RedElf가 자신의 사거리 밖에 있는 보이는 적에게 접근하지 않는 상황을 재현했다. 실제 티라노전 추적에서도 사거리 밖 적만 있는 방어 상태를 관찰했다. 이 추적만으로 장거리 적의 공격이 해당 패배의 주원인이라고 단정하지 않는다.
3. 조합 교사는 확장 예정지 `SCOUT → anchor 3`을 지시하지만 기존 마스크는 SCOUT 목적지 3을 금지했다. 교사의 정규화가 명령을 적 방향 `anchor 4`로 바꾸므로, 마스크 위반 0이라는 형식 검사만으로 이 오류를 잡을 수 없었다. 원본 조합 교사의 조건 26 기록에서도 이 명령과 확장 건설 불가 상태를 확인했다.
4. 조합 교사의 스킬 주기는 관측에 없는 `decision_count % 4`에 의존했다. 기존에 관측되는 `frame % 128` 위상으로 바꾸는 격리 후보를 만들었다. 관측 형식은 그대로이며 실제 경기에서 강도를 확인한다.
5. RedElf 수 특징이 10기에서 포화되어 전체 교사 결정 61,090개 중 32,765개에서 정확한 수가 직접 표현되지 않았다. 총 병력·전투력에 간접 정보는 있으므로 전체 관측이 동일한 모순 상태라고 단정하지 않는다. 초반 첫 생산시설에 필요한 일꾼/대기열/시설/가용·예약 자원은 관측에 존재했다.

## CEM 전략 수치 학습으로 전환

코호트 87까지 새 모방 학습 정책의 승수 증가는 입증하지 못했다. 관측되지 않는 내부 위상, 확장 정찰 목적지 오류, 자기 대상 공격 스킬, 합법 생산에 확률을 주지 못하는 트리, 공격 시작·목적지·유지 실패를 분리해 조사했지만 어느 한 수정이나 모방 정확도 향상도 전체 승리로 이어지지 않았다. 코드 오류 수정과 학습 정책 채택을 따로 판단하며, 실제 신경망 기준 모델은 v8을 유지한다. 이후 CEM 0세대도 그 세대의 영점 규칙 기준을 넘지 못했다.

후속 학습은 기존 규칙 실행기의 여섯 전략 수치를 CEM(Cross-Entropy Method)으로 탐색한다. 후보 수치로 **실제 경기를 실행하고 받은 보상**에 따라 상위 후보를 선택하여 다음 후보 분포를 갱신한다. 교사 정답의 재현율을 높이던 앞 단계와 학습 목적이 다르다. 다만 생산 전제·명령 실행·정찰·스킬·철수 처리는 검증된 규칙 실행기에 남아 있다. 실행 로그의 `teacher=true`, `weight_version=0`도 유지하고, 상위 제어기에는 `reward_optimized_elf_strategy`, `method=CEM`, `neural_actor=false`, `ppo_eligible=false`를 기록한다. 함께 배치된 v8 가중치는 이 경로의 행동을 생성하지 않는다.

| 수치 | 탐색 범위 | 실제 적용 범위 |
| --- | --- | --- |
| `worker_delta` | 정수 -4~4 | 20/28+ 일꾼 목표와 해당 목표에 진입하는 조건. 8/12/16 목표 식은 유지하지만, 기본 교사의 20명 목표는 첫 전투 유닛이 나오기 전에도 적용된다. |
| `red_scale_delta` | -0.25~0.5 | RedElf 생산 목표·생산 수 조건. 초반 Red 목표도 포함하므로 초반 운영 전체가 고정된 것은 아니다. |
| `frontline_scale_delta` | -0.5~1 | 원시인 상대 WhiteElf, 데몬 상대 BlueElf 목표, 기본 교사의 Blue 계열 비율 목표. |
| `mana_delta` | 정수 -1~4 | 조합 교사의 기존 마나엘프 목표. 기본 교사는 양수일 때 일꾼 16·병력 8 이상에서 앞선 우선 행동이 없으면 마나홀 준비와 생산을 추가한다. |
| `attack_army_delta` | 정수 -8~8 | 공격을 시작하는 병력 수를 조정하되 최솟값은 8. 비상 방어·후퇴 판단은 유지한다. |
| `attack_ratio_delta` | -0.3~0.3 | 공격 진입 전력비를 조정하되 최솟값은 0.8. |

공개 상대 종족에 따른 기존 분기는 원시인 White+후속 정찰, 데몬 Blue 조합, 엘프·티라노 기본 교사다. 여섯 수치는 이 분기의 해당 생산·진입 조건에 적용되며 시작 위치별 교사를 숨겨 선택하지 않는다. 개수 배율은 양수 `lround(n*(1+delta))`와 최솟값 1을 사용하므로 18×1.25는 23이다. 영점에서는 원래 값과 계산 경로를 바로 반환한다. 모든 전투·명령 규칙을 학습하는 범용 신경망으로 표현하지 않는다. [동결 실행기와 수치 계약](../build/elf_cem_scaffold_20260910/scaffold_manifest.json)

CEM 실행 파일은 `build/elf_cem_scaffold_20260910/ranker_rebuild.exe`, SHA `3ce9815b511360f5bf5af8d2e3a709646279fafb85f072e23a051a6597f680d1`이다. 프로필은 프로세스 시작 시 한 번 읽고 정확히 여섯 개의 유한 수·정수 조건·범위를 검사한다. 파일이 지정됐는데 없거나 잘못된 경우 영점으로 조용히 대체하지 않는다. 실행기는 각 자식 프로세스에 프로필 경로를 명시하고 이전 환경값을 제거한다. 경기 영수증은 실제 파일 SHA·CRC·파싱 값·실행 파일 SHA와 네이티브 시작 로그를 연결하여 다른 후보의 자료가 섞이지 않게 한다.

영점 사전 검증은 기존 `d430...` 실행기와 새 실행기의 프로필 없음/명시적 영점 사이에서 1,400개 전체 행동 일치를 확인했다. 정상·경계 프로필 16개와 잘못된 프로필 24개 검사도 통과했다. 이어 코호트 86/87의 새 실제 4조건에서 6,481개 결정과 종료 기록의 모든 원시 RLO 필드, 최종 결과, 결정적 게임 지표가 정확히 같았다. RLO 파일 해시도 조건별로 같았으며 실제 처리 시간 지표만 달랐다. 자기 소유자의 내장 AI 비활성화와 정상 내장 상대 설정, 실제 프로필 경로·CRC·수치도 확인했다. [네이티브 실제 경기 영점 비교](../debug_artifacts/commander/elf_reaudit_20260909/cem_native_zero_parity.json)

### 동결된 기본 교사 분기의 제약

CEM 영점은 기존 동작을 보존하므로 엘프·티라노 상대의 기본 교사 분기는 `RaceRoles`·`RaceEconomy` 옵션을 켜지 않은 상태다. 기본 확장 저축 임계값은 실제 엘프 HQ 비용 1,200보다 낮은 1,000이고, 종족 역할 보정 없이 공성 역할을 세면 Unicorn을 포함한다. 여섯 수치를 탐색한다고 이 역할 대응이나 모든 생산 전제가 자동으로 바뀌지는 않는다. 양수 `mana_delta`는 별도의 실제 마나홀/마나엘프 생산 경로를 제공하지만, 기본 분기 전체의 역할 보정을 대신하지 않는다.

실제 영점 조건 13/26은 각각 HQ를 한 번도 발주하지 않았고 BlueElf·WhiteElf·ManaSpread·ElfLibrary·지상 공방 연구가 없었다. 조용하고 확장 대기 중인 상태에서 은행 자원이 대략 1,005~1,195인 채 다른 행동을 선택한 결정은 각각 33/17개였다. 자원은 기록된 로그 정규화 특징을 역변환한 근사값이며, HQ의 실제 마스크는 이 상태들에서 불법이었다. 또한 두 조건의 적 시작 위치는 2/3이므로 `enemy_plateau=false`였다. 잘못된 Unicorn 공성 집계가 **이 두 패배를 일으켰다고 해석하지 않는다**. [원시 기록 기반 역할·비용 감사](../debug_artifacts/commander/elf_reaudit_20260909/cem_default_role_cost_audit.json)

역할·본진 비용 보정을 켠 전체 변경은 이미 정상 내장 AI·재편성 0인 같은 12조건에서 기본 2승 10패 대비 1승 11패였다. 엘프/티라노 상대 여섯 조건은 모두 패배했고, 조건 13/26은 각각 18,576/14,552프레임 패배였다. 별도 v4 조합 실험도 4조건 0승 3패 시간초과 1회였다. 이 제약은 새로 검증된 승리 해법이 아니므로 동일한 옵션 묶음을 다시 켜서 개선이라고 주장하지 않는다. CEM 탐색은 우선 동결된 실행기로 진행하고, 다른 규칙 분기를 비교할 때는 별도 실행기·기준값·프로필 출처를 사용한다. [이전 역할·경제 보정 12조건 결과](../debug_artifacts/commander/foundation_20260909/elf/teachers/variant_3221225472/screen.json)

### 첫 CEM 후보의 초반 민감도 조사

[라우터 실행 모듈](../ranker_reconstructed_code/tools/ai/ranker_commander_strategy_router.py)은 `load_router(path)`, `validate_router(binding)`, `select_strategy(binding, public_opponent_tribe)`, `bind_router_job(binding, job)` API를 제공한다. 선택 입력은 정수 공개 상대 종족 0~3뿐이다. 닫힌 JSON 스키마, 모든 프로필·실행 파일·선택 증거의 SHA, 엄격한 승수 선택 조건을 검사한다. `run_router`는 경기마다 선택된 프로필과 전체 라우터 정체성을 영수증에 남기고 실제 상대 종족·자기 내장 AI 비활성화·종료 결과·RLO를 다시 확인한다. 하위 영점 프로필의 `purpose=baseline`도 원본 그대로 보존한다.

관련 라우터 테스트 9개가 통과했다. 실제 동결 라우터를 사용한 CLI dry-run에서도 48개 서로 다른 종족/시작 위치 조건과 적용 프로필이 일치했고 파일을 바꾸거나 경기를 실행하지 않았다. [실제 CLI 검증](../debug_artifacts/commander/elf_reaudit_20260909/context_router_v2_cli_dry_run.json)

프로젝트 루트의 PowerShell에서 다음 명령으로 전체 48경기 계획을 확인한다. `--dry-run`을 빼면 지정한 새 출력 폴더에 실제 48경기를 실행한다. 기존 출력 폴더는 덮어쓰지 않는다. `--weights-placeholder`는 기존 실행 인터페이스가 요구하는 파일이며, 이 규칙 실행기의 행동을 계산하는 데 사용하지 않는다.

동결 라우터는 [router.json](../debug_artifacts/commander/race_strength_20260909/training_run/elf/contextual_strategy_v2_20260910/router.json), SHA `eda36d5050294459fdcdf9e301d53faa486118590518a3b152f329600c7fd70d`다. 실행 모듈 SHA는 `8ddf95b94d4d81692636efeb81aac08ed2b9e75d8b8d9b88744aa82517b82bb3`이다.

**코호트 103**에서는 실제 라우터로 조건 17과 39를 새로 실행했다. 엘프 상대 평균 프로필은 34,920프레임 승리, 데몬 상대 영점 프로필은 48,696프레임 승리였다. 두 영수증 모두 전체 라우터 SHA, 실제 적용 프로필, 공개 상대 종족, 네이티브 로그와 RLO 확인을 통과했다. 독립 비교에서 두 전체 RLO 파일은 원래 평균 프로필 조건 17·영점 조건 39와 바이트까지 같았다. 4,560개 결정 쌍과 종료 레코드 2개의 행동·지도·관측·마스크·보상·비공개 상태·CRC가 모두 일치했고, 종료 결과와 게임 진행 지표도 같았다. 실행 시간 측정값만 달랐다. 이 2승은 프로필 선택·실행 연결을 검증한 동일 조건 반복이며 독립적인 성능 표본이나 48조건 승수에 더하지 않는다. [새 라우터 두 경기의 실제 영수증](../debug_artifacts/commander/race_strength_20260909/training_run/elf/update_context_router_verify_20260910/teacher/full.json), [전체 RLO 재현성 감사](../debug_artifacts/commander/elf_reaudit_20260909/contextual_router_native_parity.json)

프로젝트 루트의 [play_last_replay.cmd](../play_last_replay.cmd)는 [리플레이 선택기](../ranker_reconstructed_code/tools/ai/ranker_commander_watch.py)를 호출한다. 검증된 라우터 경기에서는 전체 전략과 실제 적용된 하위 프로필을 함께 확인하고 가장 최근 경기를 재생 대상으로 삼는다. 원래 게임 명령이 담긴 리플레이를 사용하며 학습용 실행 파일을 배포하거나 원본 `ranker.exe`를 교체하는 작업은 하지 않는다. 재생 대상을 열기 전에 확인하려면 `./play_last_replay.cmd --dry-run`을 실행한다.

위 명령의 출력 경로는 리플레이 선택기가 탐색하는 `training_run/elf/<단계>/teacher` 구조를 따른다. 실행 API로 다른 외부 폴더를 지정할 수도 있지만, 그 폴더의 경기가 자동으로 마지막 경기 목록에 등록되지는 않는다.

코호트 103 직후의 선택기 dry-run은 새 라우터 검증의 `game_00001`, 엘프 대 데몬 경기를 선택했다. 전체 라우터 SHA `eda36d50…`와 실제 적용된 영점 프로필 SHA `071e7d2f…`를 함께 표시하며, 신경망 정책 버전은 `null`로 남긴다. 영점 하위 프로필을 사용한 경기라는 이유만으로 학습된 전체 라우터의 마지막 경기를 누락하지 않는다. 현재 진행 중인 학습 경기는 없다.
