## 원인과 수정 범위

기존 앵커 12는 시작점을 탐색한 뒤 베리 지대의 건설 부지만 순회했다. 원시인 seed 1044의 PPO 수집 경기에서는 후반 주력 중심이 x 305~3,676, y 172~3,920으로 이동했지만, 이동 가능 타일이 절반 이상인 256픽셀 구역 17곳은 끝까지 미탐색이었다. 알려진 적 건물은 0인 동안 실제로는 적 HQ 1개가 남아 60,000프레임 절단이 됐다.

별도 복사본의 수정은 모든 시작점이 탐색됐고 알려진 적 건물이 없을 때, 주력 위치에서 공개 지형으로 연결된 비가시 타일을 수색 대상으로 추가한다. 미탐색 타일을 먼저 선택하고, 이미 탐색한 곳은 최근에 덜 본 타일을 우선한다. 선택한 목표는 관측할 때까지 유지하며, 다른 적 건물을 공격하는 동안 그 목표를 관측했다면 이후 다시 선택하지 않는다. 비가시 적 개체나 critic 전용 정보는 목표 선정에 사용하지 않는다.

후보는 `debug_artifacts/commander/host_5625u_20260906/sweep_coverage_candidate`에 있다. 작업 트리의 소스와 `build/ranker_rebuild.exe`는 보존했다. 헤더의 실행 상태 크기가 바뀌어 별도 게임 파일은 커맨더와 `ranker_winmain.cpp`를 모두 다시 컴파일했다. 나머지 기존 오브젝트의 해시를 확인해 링크했으며 배포용 post-build 명령은 실행하지 않았다.

## 집중 검증

기존 코드에서 자원 지대 밖의 도달 가능한 안개 구역을 누락하는 회귀 실패를 재현했다. 후보는 관련 새 검사 7개와 기존 커맨더 회귀 21개를 통과했다. 검사 범위는 탐색 누락, 시작점 우선순위, 목표 유지와 진행, 단절된 지형 제외, 비가시 개체 차단, 알려진 건물 우선순위, 교전 중 관측한 목표의 재사용 방지다.

같은 가중치·version·시드·시작 조건으로 다음 세 실패를 실행했다. 각 기준 경기는 60,000프레임 절단이었다.

첫 번째 조건을 기존 실행 파일로도 재실행했다. 다시 60,000프레임 절단이 됐고 **2,284개 기록을 포함한 RLO 파일 전체의 SHA-256이 저장본과 일치**했다(`96fcb818212f8032b34ce32a90af6a356852ba09fafc2db54e9fba6e69a188c3`). 후보와 기준의 동일한 기록 접두부는 각각 906·821·2,137개였다. 이것은 선택한 실패 사례에서의 수정 효과이며 전체 승률이나 전승 게이트 결과는 아니다.

첫 변경 시점은 세 경기 모두 알려진 적 건물 0·미탐색 시작점 0이며 새 목표 타일은 비가시 상태였다. 원시인 1044와 101은 각각 19,713·21,345프레임에 마지막 HQ를 관측 또는 관측 기억으로 확보한 뒤 승리했다. 기존 경로에서는 해당 시점 이후에도 적 건물을 찾지 못했다. 데몬 109는 첫 변경 시점에 실제 HQ가 아직 3개였으므로 초기 건물 발견과 마지막 HQ 발견을 구분했다. 기존 경로는 41,185프레임부터 건물 1개가 남았으나 끝까지 찾지 못했고, 후보는 42,081프레임부터 1개가 남은 뒤 43,137프레임에 좌표 (256,224)의 마지막 HQ를 찾아 승리했다. 실제 적 개수는 기록 분석에만 사용했으며 실행기의 목표 선정에는 입력하지 않았다(`focused_target_discovery.json`).

네 경기는 모두 정상 완료됐다. 이후 집계 코드가 `DecodedRecords.view`를 호출해 실패한 부분은 `Episode.raw_records` 비교로 수정했다. 원래 수집 소스와 오류 상태를 보존하고 완료된 기록만 재분석했으며 경기를 중복 실행하지 않았다.

근거는 후보 폴더의 `baseline_check.json`, `candidate_checks.json`, `game_build_provenance.json`, `focused_plan.json`, `focused_results.json`과 `focused_games`의 개별 경기 기록이다.

최종 240경기가 전부 유효했고 마스크 위반은 0이었다. 전체 묶음에서 획득 조건은 없고 BC·정속 최고 PPO가 같은 엘프 시작 조건을 각각 잃었으므로 첫 후보는 채택하지 않았다. 실제 프로세스 종료·exit 0·입력 해시 보존은 `closure_verification.json`, 최종 판단은 `assessment_decision.json`에 보존했다. 후속 컨트롤러가 보유한 실제 Windows 핸들로 정상 종료를 확인한 다음 5개 집중 검증을 시작했다.

첫 묶음인 교사 C2는 **41/48승**, 모든 조건의 승패가 기존과 같고 획득·상실 조건은 0개였다. 전 48경기 유효·마스크 위반 0이며 종족별 승수는 12/11/7/11이다. **46경기는 종료 프레임과 모든 결정 레코드가 바이트 단위로 일치**했고, 종국 관측까지 포함한 전체 레코드 일치는 31경기였다. 달라진 데몬 seed 11·2는 모두 승리했지만 종료 프레임이 각각 27,435→28,320, 20,716→26,563으로 늘었다. 따라서 승패 보존과 모든 경기의 종료 시간 보존을 구분한다. 근거는 `full_validation/teacher_C2/comparison.json`과 `behavior_preservation_audit.json`이다.

데몬 두 경기에서는 같은 마지막 HQ를 각각 기존 27,265·20,513프레임, 후보 28,193·26,273프레임에 찾았다. 넓은 수색 순서로 바뀐 뒤 발견이 늦어진 경로이며, 기존 승리가 더 빨랐다는 사실도 보존한다(`full_validation/search_regression_diagnosis.json`).

두 번째 BC 기준 묶음은 **40/48승**으로 기존보다 1승 줄었다. 엘프 seed 2, 시작 (1,2)가 22,157프레임 승리에서 60,000프레임 절단으로 바뀌었고, 새로 얻은 승리는 없다. 894개 레코드가 일치한 뒤 17,473프레임부터 경로가 달라졌다. 후보의 30k 이후 945결정 모두 MAIN은 ATTACK_MOVE·앵커 12 상태였고 목표는 (3376,2448)·비가시 상태로 고정됐다. 주력 중심은 목표에서 약 49~76픽셀 거리에 머물렀고 x·y 이동 범위는 각각 24픽셀뿐이었다. 실제로는 HQ가 아닌 적 건물 2개가 남았다. 단순한 정적 지형 연결 여부와 실제 대형의 이동·시야 확보 성공은 같지 않으며, 관측할 때까지 무조건 목표를 유지하는 규칙에 정체 해소 조건이 없었다. 이 후보는 해당 회귀를 해소하기 전에는 채택하지 않는다.

## 정체 재시도 후속 후보

`sweep_coverage_retry_candidate`에 첫 후보와 분리해 준비했다. 실제 MAIN 수색 중 목표까지 32픽셀을 넘게 가까워지는 진전이 1,024프레임 동안 없으면 해당 타일을 4,096프레임 동안 뒤로 미뤄 다른 비가시 타일을 시도한다. 이후 재시도할 수 있으며, 실패를 관측·탐색 완료로 기록하지 않는다. 이동이 진행 중이면 목표를 유지하고, 미선택 수색 목표나 알려진 적 건물과의 교전 시간은 정체로 계산하지 않는다. MAIN의 SCOUT 명령은 가장 빠른 한 기만 움직이므로 이 경우에는 대형 중심 대신 실행기가 선택하는 정찰병의 위치로 진전을 측정한다. 종족·시드·가중치·비가시 적 정보에 따른 분기는 없다.

첫 후보에서 `stalled search target never advanced` 회귀 실패를 재현했다. 후속 후보는 기존 수색 검사 7개와 정체·장거리 이동·미선택 목표·재시도·교전 중단·단독 정찰 관련 6개를 합쳐 **13개 검사**, 기존 커맨더 **21개 검사**를 통과했다. 근거는 후속 폴더의 `stall_baseline_check.json`, `candidate_checks.json`이다. 첫 후보의 전체 검증과 원본 입력은 계속 보존한다. 게임 검증 전이므로 후속 후보의 승률 회복은 아직 확인되지 않았다.

후속 게임 빌드는 89.37초에 완료됐고 실행 파일 SHA-256은 `5f7c5aa40d059c6048720b75a8b46f5e3059cca052703d6a309050dcef2fccee`다. C++·헤더는 각각 `adc03589af15502e3c4f5a8619d136528ebb0224215ca518f6a40190a9dee7ce`, `abfa7a5f7d186b7fa175abdc63aff5d60d7637dfb2943cf06b0d8be2c5fbb742`이며 작업 트리·기존 오브젝트·기존 실행 파일을 보존했다. 배포 post-build는 실행하지 않았다(`game_build_provenance.json`).

첫 후보의 세 번째 묶음인 정속 최고 PPO는 **42/48승**으로 기존보다 1승 줄었다. BC와 같은 엘프 seed 2, 시작 (1,2)가 23,210프레임 승리에서 절단으로 바뀌었으며 획득 조건은 없다. 후반 군 병력과 자원은 관측 상한에 도달했고 MAIN은 ATTACK_MOVE·앵커 12 상태를 유지했다(`full_validation/best_argmax/comparison.json`, `truncation_diagnosis.json`).

후속 컨트롤러는 **PID 8788**(부모 11700), `run_validation.py`다. 첫 컨트롤러 PID 19504의 Windows 프로세스 핸들을 보유해 실제 정상 종료까지 기다렸으며 그동안 새 게임 worker는 0개였다. 종료 뒤 입력 해시를 확인하고 기존 수색 실패 3건과 첫 후보의 전체 평가에서 새로 잃은 모든 승리 조건을 같은 가중치·version·시드로 재검증했다. 모두 승리해 같은 5개 전체 묶음 240경기를 이어서 평가한다. 상태 `validation_state.json`, 대기 계획 `waiting_plan.json`, 시작 전 확인 `launch_preflight.json`, 로그 `validation.log/.err`에 보존했다. 두 컨트롤러가 게임을 동시에 수집하지 않아 게임 worker 합계는 4개다. 이 절차는 후보 검증이며 PPO 학습·전승 게이트·리그 승격은 수행하지 않는다.
