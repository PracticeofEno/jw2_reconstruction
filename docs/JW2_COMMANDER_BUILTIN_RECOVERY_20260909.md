## 2026-09-09 트랩의 종료 판정 제외 누락 교정

트랩(`0x6a`)은 게임 종료 조건의 건물에 포함되지 않는다. 일반 게임의 종료 판정과 Commander RLO의 최종 승패는 이미 이 규칙을 따랐지만, `-AISELF`의 경기 종료 검사와 결과 JSON은 `type_id >= 0x60`을 사용해 트랩을 건물로 세고 있었다. 따라서 트랩만 남은 진영 때문에 자동 경기가 시간 제한까지 이어지면서 패배 후 행동도 학습 자료에 기록될 수 있었다. 앞선 파일·종족·가중치 무결성 검사만으로는 이 종료 시점 오류를 잡지 못했다.

기존 원본 종료 판정과 같은 `IsGameplayEliminationBuildingType`을 공유하도록 자동 경기 종료·결과 JSON·기존 RL/Entity 종료 보상 경로를 교정했다. Commander의 기존 트랩 제외 판정도 같은 함수를 사용한다. 일반 게임/P2P의 종료 규칙과 유닛의 생산·전투 분류는 바꾸지 않았다.

## 2026-09-09 오후: 데이터 재점검과 기초 전략 우선 전환

기존 소량 승리 자료 BC → PPO 순회는 **14:47:33에 중지 완료**했다. 원시인 v23의 마지막 개발 평가는 argmax 1/24, sampling 0/24, 합계 1/48이어서 기존 최선 v20을 유지한다. 새 작업은 `debug_artifacts/commander/foundation_20260909`에서 **종족별 교사 전략 선별 → 강한 교사의 자료로 BC → 정책 실패 상태의 DAgger → 실제 경기 검증 → PPO** 순서로 진행한다. 새 작업의 PPO는 아직 허용하지 않는다. 티라노 가중치는 동결한다.

티라노의 앞선 BC에는 교사 360경기·508,798행동과 DAgger 252경기·332,312행동, 합계 **612경기·841,110행동**을 사용했다. 검증 자료는 별도로 51경기다. 다른 종족에 이번에 보강한 승리 자료는 엘프 **6경기·9,311행동**, 데몬 **13경기·21,735행동**, 원시인 **10경기·13,655행동**이다. `builtin_recovery_20260909/foundation_data_audit.json`에서 29개 RLO의 해시·actor fingerprint·종족 one-hot·소유자·시드·가중치 버전·완료 승리·정상 내장 AI·C2·행동 재편성 방식·마스크 위반을 다시 대조했고 모두 통과했다. 이는 자료의 무결성 확인이며 강한 기초 전략을 충분히 배웠다는 뜻은 아니다.

**평가 범위에 대한 정정:** 초기 복구의 “48경기”는 argmax 24 + sampling 24다. argmax의 실제 상대 종족/시작 위치 조건은 엘프 **19개**, 데몬 **18개**, 원시인 **24개**뿐이었다. 엘프·데몬에는 반복 조건이 있고, 세 종족 모두 일부 조건이 학습 자료와 겹친다. 시드 범위를 바꿨다는 이유로 독립 조건이 되는 것은 아니다. 기존 1/48·9/48·2/48은 이 제한이 있는 개발 평가 결과이며 티라노의 서로 다른 48조건 평가와 동등하게 비교하지 않는다.

새 드라이버 `ranker_commander_foundation.py`는 티라노에서 검증한 실제 위치 계획을 가져와, 상대 4종족 × 순서가 있는 시작 위치 12쌍을 정확히 확인한다. 선별 인덱스는 `0,5,10,13,18,23,26,31,32,39,40,45`다. 상대당 3경기이며 12개 시작쌍을 모두 포함한다. 교사는 선별 8/12 이상인 후보에만 전체 검증 비용을 쓰고, 검증된 선별 12경기를 재사용해 나머지 36경기만 추가한다. 기초 교사의 잠정 통과 기준은 전체 **36/48 이상**, 상대별 **6/12 이상**, 금지 행동 0건이다. 이는 작업 진행 기준이며 통계적 일반화 보장이 아니다.

교사와 모델은 모두 `coordinated_transfers=0`, 현재 native 관측 schema `0x7EEED592`, 정상 내장 AI, C2, 최대 60,000 frame을 사용한다. 이전의 `coordinated_transfers=1` 교사 시험은 다른 행동 의미를 사용하므로 이 학습 자료에 자동 편입하지 않는다. 구형 RLO의 새 관측을 0으로 채운 자료도 학습에 넣지 않는다. 교사 변형 번호와 실제 실행 플래그, 시작 로그, RLO, 완료 결과, 가중치, 원본 자원, 실행파일, Python/native 소스의 해시를 계약으로 기록한다.

전체 검증을 통과한 교사의 승리 자료만 BC에 넣는다. DAgger는 통과한 같은 종족·같은 교사의 라벨만 사용하며, 정책이 실제 방문한 native 관측과 행동 이력은 보존하고 라벨/조건부 마스크만 대체한다. 학습·검증은 **상대 종족/실제 시작 위치 단위**로 나누어 시드 별칭과 교사 변형이 분할을 넘지 못하게 하고 actor 중복도 제거한다. BC의 희귀 행동 가중치 8, 클래스 power .5/cap 20을 적용하되 부대 재편성 38–41의 과도한 재가중은 제외한다. BC 정확도만으로 PPO나 배포를 승인하지 않는다.

실험용 교사에는 종족별 병력 역할·생산 선행 조건 보정과 본진 실제 비용 보정이 독립적으로 선택 가능하다. 원본 비용은 원시인 Sanctuary·엘프 Heaven·데몬 Den 1,200, 티라노 Nest 1,000이다. 기본 교사의 1,000 저축 임계값을 실제 생산 비용으로 바꾸는 실험은 별도로 대조한다. 경제 보정만으로 승률이 오를 것이라고 가정하지 않는다. 실험 실행파일은 `build/commander_race_teacher/ranker_rebuild.exe`이며 설치 폴더의 실행파일을 배포·교체하지 않았다.

기존 재편성=1 교사 경기와 맞춘 경제 보정 단독 대조 12경기는 엘프 0/4, 데몬 0/4, 원시인 0/4(2패·시간 초과 2)로 끝났다. 기존 합계 2승보다 나빠져 채택하지 않았다. 실제 추가 본진이 지어진 것은 확인했지만 이것만으로 더 강한 전략이 되지는 않았다. `builtin_recovery_20260909/teacher_economy_probe.json`에 경기별 전후 결과와 확장 시점이 있다. 따라서 경제 보정 단독안의 추가 선별은 생략하고 역할·생산 조건을 함께 보정한 전략을 우선 비교한다.

코호트 결과는 이 채팅에서 전달한다. Windows 알림 옵션은 사용하지 않는다. 기존 보고 수집기의 일시적 Windows 파일 잠금 오류에는 재시도를 추가했다. 파일에 기록하는 것 자체가 대화 메시지를 전송하는 것은 아니며, 채팅 전달은 작업 중인 어시스턴트가 수행한다.

## 실행과 관전

프로젝트 루트의 `play_last_replay.cmd`를 실행하면 가장 최근에 **정상적으로 완료된 학습 또는 평가 경기**의 `.ply`를 자동으로 연다. 진행 중인 경기, 실행 실패, 교사 시험 경기는 제외한다. 시간 제한으로 끝난 정상 경기는 포함한다. 가중치를 다시 실행해서 경기를 새로 만드는 방식이 아니라 저장된 명령을 재생한다.

학습 정책 쪽의 내장 AI는 비활성화한다. 원래 상대였던 내장 AI는 계속 동작해야 기록한 경기가 재현된다. 실행 시 전용 관전 폴더에 리플레이를 복사하므로 원본 기록과 설치 폴더는 수정하지 않는다.

```bat

```

`--dry-run`은 창을 열지 않고 선택된 경기, 종족, 시드, 종료 시각, 가중치 해시를 출력한다. 실제 관전 기록은 `debug_artifacts/replay_viewer/latest_*/selected_match.json`과 `viewer.log`에 남는다.
