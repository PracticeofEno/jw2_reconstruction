# AI 학습 방향 변경 — 쉽게 보는 Before → After

> 기준: 2026-09-01 현재 작업 트리
>
> 이 문서는 구현 세부사항보다 **무엇을, 왜 바꾸었는지**를 쉽게 설명한다.
> 정확한 데이터 구조와 계약은 문서 맨 아래의 상세 설계 링크에서 확인할 수 있다.

## 먼저 이것만 읽기

예전 AI는 장군처럼 **“적 기지를 공격하라”** 같은 큰 목표만 정했다.
실제로 어떤 유닛이 누구를 공격하고 언제 물러날지는 규칙 기반 실행기가 결정했다.

새 AI는 8 frame마다 각 전투 유닛에 **유지·이동·공격·대기** 같은 실제 명령을
직접 내린다. 실행기는 전술가 역할에서 물러나, 명령을 검사하고 게임에 안전하게
전달하는 역할을 맡는다.

다만 이번 변경은 전투 제어의 첫 단계다. 생산·건설·연구와 일꾼 경제는 아직 기존
방식을 사용하며, 기존 AI 학습 경로도 삭제하지 않았다.

## 실제 게임에서는 무엇이 달라지나

### Before

```text
학습 모델: "적 본진을 공격해"

규칙 기반 실행기:
- 어느 유닛을 보낼지 결정
- 어떤 적을 먼저 공격할지 결정
- 체력이 낮으면 언제 물러날지 결정
- 부대가 흩어지면 어디서 기다릴지 결정
```

학습 모델은 공격이라는 큰 의도만 골랐다. 전투의 세부 행동은 대부분 코드에 적힌
규칙의 결과였다.

### After

```text
학습 모델:
- 검병 A: 적 궁수 3번 공격
- 검병 B: 현재 공격 유지
- 궁수 C: 서쪽으로 이동
- 궁수 D: 제자리 대기

실행기:
- 유닛과 표적이 아직 살아 있는지 확인
- 불가능한 이동이나 공격을 거절
- 이미 같은 명령이면 다시 보내지 않음
- 유효한 명령을 게임 packet으로 전달
```

이제 집중 공격, 거리 조절, 명령 유지 시점 같은 전투 행동도 규칙이 아니라 학습의
결과가 될 수 있다.

## 1. 한눈에 보는 핵심 변화

| 영역 | Before | After | 중요한 의미 |
|---|---|---|---|
| 학습 대상 | 공격·방어 같은 큰 전략 | 전투 유닛별 실제 명령 | 세부 전투도 학습 가능 |
| 학습 자료 | packet이나 경기 상태 변화로 큰 행동을 추정 | 기존 AI가 내리려던 유닛별 명령을 바로 기록 | 더 구체적인 정답 사용 |
| 정책 입력 | 병력·경제 등을 합친 802개 요약 정보 | 기존 요약 + 아군 유닛 목록 + 보이는 대상 목록 | 개별 유닛 상태를 보고 판단 |
| 정책 출력 | 부대 전체의 큰 행동 1개 | 각 전투 유닛의 명령 | 유닛마다 다른 행동 가능 |
| 액션 | 80-slot macro에서 큰 행동 하나 | macro 계약 유지 + 전투 유닛마다 7개 명령 | 전투용 명령 체계를 별도로 추가 |
| 실행기 | 유닛·표적·후퇴까지 대신 판단 | 가능 여부 검사, 중복 제거, packet 전달 | 전술 판단이 정책으로 이동 |
| 경제 운영 | 정책과 자동 규칙이 함께 담당 | 생산·건설·연구와 일꾼은 기존 방식 유지 | 현재 단계는 전투에 집중 |

## 2. 학습 방법은 어떻게 바뀌었나

### Before: 큰 행동을 사후에 추정

예전 imitation 학습은 한 시점에 high-level action 하나를 학습했다.

- replay packet에서 행동을 정확히 읽을 수 있으면 그 값을 사용했다.
- 정확한 값이 없으면 유닛 생산 완료, 건물 변화, 적과의 거리 변화 같은 다음 상태를
  보고 이전 행동을 추정했다.
- 따라서 “공격했다”는 큰 행동은 알 수 있어도, 어떤 유닛이 어떤 명령을 얼마나
  유지했는지는 알기 어려웠다.

### After: 기존 AI의 유닛 명령을 먼저 따라 배우기

권장 학습 흐름은 다음 세 단계다. 온라인 trainer를 새 모델로 바로 시작할 수도 있지만,
보통은 Shadow 모방 학습으로 기본기를 익힌 뒤 PPO로 넘어가는 편이 안정적이다.

#### 1단계 — Shadow 데이터 수집

기존 scripted AI가 실제로 게임을 플레이한다. 새 AI는 제어권을 갖지 않고,
8 frame마다 기존 AI가 각 전투 유닛에 내리려던 명령을 기록한다.

예를 들어 다음과 같은 정답이 저장된다.

```text
유닛 101: 현재 명령 유지
유닛 104: 동쪽으로 이동
유닛 108: 적 유닛 55 공격
```

#### 2단계 — 모방 학습(BC)

새 모델이 Shadow 데이터를 따라 하며 기본 조작을 익힌다.

- 언제 기존 명령을 유지할지
- 언제 새 이동 명령을 내릴지
- 어떤 적을 공격할지
- 언제 대기하거나 정지할지

처음부터 무작위로 전투하는 것보다 안정적인 출발점을 만드는 단계다. 다만 teacher는
사람이나 최적 정책이 아니라 **기존 scripted AI**이므로, 기존 AI의 한계도 함께 배울 수 있다.

#### 3단계 — 실제 경기 강화 학습(PPO)

모방 학습 뒤에는 built-in Computer와 실제 경기를 하며 결과로 개선한다.

현재 보상은 단순하다.

```text
보상 = 5 × (적 유닛·건물 손실 증가분 - 내 유닛·건물 손실 증가분) / 1000
       + 최종 승패

승리 +6 / 패배 -6 / 무승부·시간 종료 0
```

경제 성장, 적에게 가까이 간 것, 특정 명령을 사용한 것에는 별도 보상을 주지 않는다.
즉 실제 전투 손익과 승패를 중심으로 학습한다.

## 3. 정책은 어떻게 바뀌었나

### Before: 팀 전체 요약만 보고 큰 목표 선택

기존 정책은 경제, 병력 수, 연구, 전장 격자 등을 합친 802개 요약 정보를 보고
80개 high-level action 중 하나를 골랐다.

그 결과는 다음과 같은 형태였다.

```text
공격 / 방어 / 후퇴 / 정찰 / 생산 / 건설 / 연구 ...
```

### After: 유닛 카드를 보고 각 유닛의 명령 선택

새 `EntityNet`은 기존 802개 팀 요약에 다음 정보를 추가로 본다.

- 아군 전투 유닛 카드: 위치, 체력, 속도, 사거리, 현재 이동 상태 등
- 보이는 대상 카드: 적 유닛·건물과 중립 몬스터의 위치, 체력, 종류 등
- 불가능한 명령 목록: 갈 수 없는 위치나 공격할 수 없는 대상을 미리 제외

그리고 각 전투 유닛에 대해 순서대로 결정한다.

```text
1. 현재 명령을 유지할까, 새 명령을 내릴까?
2. 새 명령이라면 어떤 명령인가?
3. 이동이라면 어디로 갈까?
4. 지정 공격이라면 누구를 공격할까?
```

정책망도 기존 전장 격자와 요약 수치 중심 구조를 그대로 확장하지 않았다. 같은 종류의
유닛 카드는 같은 방식으로 읽고, 이를 팀 전체 상황과 합쳐 각 유닛의 행동을 고른다.

## 4. 액션은 어떻게 바뀌었나

각 전투 유닛은 다음 7개 중 하나를 고른다.

| 번호 | 명령 | 쉬운 의미 |
|---:|---|---|
| 0 | `KEEP_CURRENT_ORDER` | 지금 하던 행동 계속하기 |
| 1 | `MOVE` | 지정 위치로 이동하기 |
| 2 | `ATTACK_MOVE` | 이동하면서 만나는 적 공격하기 |
| 3 | `PATROL` | 지정 위치를 순찰하기 |
| 4 | `ATTACK_UNIT` | 보이는 특정 대상을 공격하기 |
| 5 | `HOLD_POSITION` | 현재 위치를 지키기 |
| 6 | `STOP` | 현재 행동 멈추기 |

이동 위치는 두 종류를 함께 사용한다.

- 전장 전체를 8×8로 나눈 64개 큰 위치
- 현재 유닛 주변의 32개 가까운 위치

따라서 유닛은 총 96개 위치 후보 중 하나를 고를 수 있다. 지정 공격은 좌표를 찍는
대신 현재 보이는 공격 가능 대상 목록에서 하나를 직접 고른다.

> **오해 주의:** 액션 전체가 80개에서 7개로 단순히 줄어든 것이 아니다.
> 기존 80-slot high-level 계약은 남아 있다. 새 경로에서는 그중 생산·건설·연구
> 계열만 사용하고, 전투 유닛마다 별도의 7개 명령 인터페이스를 추가했다.

## 5. 실행기는 어떻게 바뀌었나

실행기의 역할을 한마디로 말하면 **전술가 → 안전 검사원 겸 배달원**이다.

| 역할 | Before | After |
|---|---:|---:|
| 공격할 유닛과 표적 선택 | 실행기 | 학습 모델 |
| 저체력 후퇴 판단 | 실행기 규칙 | 학습 모델이 배워야 함 |
| 부대 간격·대기·진입 판단 | 실행기 규칙 | 학습 모델이 배워야 함 |
| 유닛이 살아 있고 내 소유인지 검사 | 실행기 | 실행기 |
| 이동·공격 가능 여부 검사 | 실행기 | 실행기 |
| 같은 명령 반복 전송 방지 | 실행기 | 실행기 |
| 게임 packet 생성과 전송 | 실행기 | 실행기 |

새 실행기는 학습 모델의 합법적인 전투 결정을 더 좋은 전술로 몰래 바꾸지 않는다.
대신 오래된 유닛 정보, 죽은 표적, 불가능한 이동, 중복 명령을 걸러낸다.

동시에 제어하는 여러 AI 진영의 같은 frame 명령은 먼저 검증하고 packet으로 계획한다.
그 뒤 계획된 packet 묶음을 전부 게시하거나 전부 보류한다. 이는 simulation을
되돌린다는 뜻이 아니라, 그 frame의 packet을 일부만 게시하지 않는다는 뜻이다.

## 6. 바뀌지 않은 것과 현재 경계

### 기존 경로는 그대로 남아 있다

새 방식은 `-AIENTITY:PORT`로 켜는 별도 경로다. 기존 `-AIIPC` high-level 정책과
기존 trainer/self-play 도구를 삭제하거나 완전히 교체하지 않았다.

### 경제는 아직 새 모델의 학습 대상이 아니다

- 생산·건설·연구 macro는 현재 가능한 행동 중 하나를 server가 무작위로 고른다.
- 일꾼 채집과 경제 운영은 기존 scripted 실행기가 계속 처리한다.

### 직접 제어하는 유닛도 아직 제한적이다

현재는 살아 있고 완성된 근접·원거리 이동 전투 유닛만 직접 제어한다.
일꾼 직접 제어, 수송, 변신, stance, item, ability는 후속 범위다.

macro 없이 일꾼의 채집·건설, 건물의 생산·연구까지 직접 제어하는 후속 계약은
[ENTCMD02 직접 경제·전투 제어 계획](../ranker_reconstructed_code/docs/AI_PLAY_ENTCMD02_DIRECT_ECONOMY_PLAN.md)에
설계되어 있다. 이 문서는 아직 구현 완료를 뜻하지 않는다.

### 실제 P2P에는 아직 사용하지 않는다

현재 entity AI 경로는 로컬 AI 학습·평가용이다. network player가 2명 이상인 실제
P2P 게임에서는 이 경로를 실행하지 않는다.

## 7. 지금 어디까지 구현됐나

| 상태 | 내용 |
|---|---|
| 구현됨 | 유닛·대상 관측, 불가능한 행동 차단, 7개 전투 명령 |
| 구현됨 | Shadow 기록과 유닛별 모방 학습 |
| 구현됨 | built-in Computer 상대의 기본 PPO 학습 |
| 구현됨 | binary `act2` 통신, 실행 결과 `OUTCOME` 반환 |
| 부분 구현 | 생산·건설·연구 연결은 있으나 learned macro는 아직 없음 |
| 부분 구현 | 명령 추적기는 있으나 일부 진행 상태가 다음 관측에 완전히 들어가지 않음 |
| 부분 구현 | 팀 상황 평가와 학습 안정화·평가·재개 기능은 더 개선해야 함 |
| 후속 목표 | mirrored combat curriculum, entity self-play, league, DAgger |
| 후속 목표 | 일꾼·수송·변신·특수 능력까지 직접 제어 |
| 현재 범위 밖 | live P2P에서의 직접 entity 정책 제어 |

현재 온라인 학습은 여러 경기를 동시에 돌리는 league 방식이 아니다. built-in Computer와
한 경기씩 순서대로 플레이하고, 경기 종료 뒤 학습을 마친 후 다음 경기를 시작한다.

## 8. 용어를 쉽게 풀면

| 용어 | 이 문서에서의 뜻 |
|---|---|
| 정책, policy | 게임 상태를 보고 행동을 고르는 학습 모델 |
| entity | 개별 전투 유닛 또는 공격 대상 |
| macro | 생산·건설·연구처럼 느린 주기의 큰 명령 |
| Shadow | 기존 AI가 내리려던 명령을 관찰만 하며 저장하는 방식 |
| BC | 저장한 정답을 따라 배우는 모방 학습 |
| PPO | 실제 경기를 하고 보상으로 행동을 개선하는 강화 학습 |
| mask | 불가능한 행동을 선택지에서 미리 제외하는 장치 |
| frame | 게임 simulation이 한 번 진행되는 시간 단위 |
| packet | 게임 엔진에 명령을 전달하는 데이터 |
| OUTCOME | 명령이 유지·중복 제거·packet 게시·검증 거절됐는지 알려 주는 즉시 결과 |

## 9. 개발자용 짧은 참고

| 항목 | 현재 값 |
|---|---|
| 전투 명령 결정 주기 | 8 frame |
| 기존 전역 요약 | 802 features |
| 유닛별 명령 수 | 7 |
| 이동 위치 후보 | 96 |
| 온라인 상대 | fixed built-in Computer |
| 온라인 update | 전체 경기에서 epoch당 최대 1,024 timestep을 뽑아 64개씩 학습 |
| 통신 경로 | binary `act2` |
| checkpoint 재시작 | optimizer 없이 model weight만 이어 쓰는 warm-start |
