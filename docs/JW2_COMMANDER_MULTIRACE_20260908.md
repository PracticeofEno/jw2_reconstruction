# 종족별 Commander 강화학습과 자기대전

엘프·데몬·원시인·티라노가 같은 학습 실행기를 사용하되, 종족마다 독립된 정책과 Adam 상태를 저장한다. 각 종족의 기본 AI 상대 학습 및 평가가 진행된 뒤 기준을 충족하면 네 종족의 과거 정책을 상대하는 자기대전으로 자동 전환한다.

**후속 변경:** 능동 스킬 선택을 추가한 새 계약과 실행 경로는 [종족·유닛 스킬 확장](JW2_COMMANDER_SKILLS_20260908.md)에 정리했다. 이 문서의 642 입력·64 매크로와 아래 실행 경로는 스킬 확장 전 기록이다. 기존 캠페인은 보존한 채 중단했으며, 현재 상태는 `debug_artifacts/commander/skills_20260908/training_run/state.json`에서 확인한다. 스킬을 선택할 수 있도록 연결한 상태와 학습을 통해 숙련된 상태는 구분한다.

실제 진행 상태는 `debug_artifacts/commander/multirace_20260908/training_run/state.json`, 실행 로그는 같은 폴더의 `runner.stdout.log`, 오류 로그는 `runner.stderr.log`에 있다. 현재 정책은 `races[종족번호].policy`, 완료 회차는 `updates`, 완료 학습 경기는 `games`다. 종족을 순서대로 학습하므로 초기에는 완료 회차가 서로 다르다.

|---|---:|---|
| 엘프 | 1 | `elf` |
| 데몬 | 3 | `demon` |

## 학습 순서와 전환 기준

1. **적응 학습:** 엘프 → 데몬 → 원시인 → 티라노 순서로 회차당 12경기를 수집한다. 새 종족의 첫 두 회차는 느린 기본 AI 상대 C1에서 가치망만 갱신한다. 3회차부터 정상 속도 C2에서 행동 정책도 PPO로 갱신한다. 티라노는 첫 회차부터 PPO를 적용한다.
2. **주기적 평가:** 각 종족을 4회차마다 48경기 평가한다. 최댓값 행동 선택 24경기, 확률적 선택 24경기이며 각 방식에서 상대 네 종족을 6경기씩 배정한다. 학습 시드와 평가 시드는 분리한다.
3. **자기대전 전환:** 모든 종족이 최소 8회차를 완료하고, 각각 최댓값 선택 승률 60% 이상, 확률적 선택 승률 50% 이상, 상대 종족별 합산 승률 25% 이상을 충족해야 한다. 평가 누락 또는 금지 행동 선택이 있으면 통과하지 않는다.
4. **계속 학습:** 자기대전에서는 장기 배정 비율로 과거 모델 상대 80%, 기본 AI 상대 20%를 사용한다. 상대 종족을 균등 순환하고 같은 종족 안에서는 승률이 낮은 과거 모델을 더 자주 선택한다. 학습 주체의 플레이어 자리를 번갈아 배정하며 해당 주체의 로그로만 갱신한다. 이 단계에서도 주기적 기본 AI 평가를 계속한다.

종족별 상대 풀은 최대 8개다. 초기 전이 모델과 가장 좋은 평가 기록의 모델을 보존하고 나머지는 최근 모델로 채운다. `best_evaluated`는 반복 개발 평가에서 관측한 최고 점수이며 배포 승인이나 독립 일반화 성능을 뜻하지 않는다. 평가 시드가 반복되므로 승률 개선 여부는 별도 신규 시드·맵 평가로 추가 확인해야 한다. 현재 실행 환경은 기존 Commander의 고정 지도다.

현재 설정은 작업자 4개, PyTorch 스레드 4개, 학습률 `2.5e-5`, 회차당 3 epoch, minibatch 2048, 32프레임 기준 gamma 1.0 / GAE lambda 0.98이다. 기본 실행은 24순회 후 체크포인트를 보존하고 멈춘다. 기준에 도달하지 못하면 bootstrap을 유지하며, 시간 경과만으로 자기대전을 강제하지 않는다.

## 실행·확인·중단·재개

작업 공간 루트의 PowerShell에서 실행한다. Torch가 설치된 `.venv-ai`를 사용한다.

```powershell
$racePython = '.venv-ai/Scripts/python.exe'
$raceTool = 'ranker_reconstructed_code/tools/ai/ranker_commander_multirace.py'

& $racePython $raceTool status
& $racePython $raceTool stop
& $racePython $raceTool train --cycles 24
```

`stop`은 현재 경기 묶음과 체크포인트를 마친 뒤 멈춘다. 평가 중이면 그 평가까지 마친다. `train`은 마지막 완료 회차의 가중치와 Adam 상태를 읽어 이어가며 기존 중단 요청을 해제한다. 이미 학습기가 실행 중이면 파일 잠금이 중복 실행을 막는다. 컴퓨터를 재시작한 뒤에는 `train`을 다시 실행해야 한다.

새 전이 실험을 만들려면 비어 있는 작업 폴더를 지정한다.

```powershell
& $racePython $raceTool init --work-dir debug_artifacts/commander/my_race_run
& $racePython $raceTool train --work-dir debug_artifacts/commander/my_race_run --cycles 24
```

실행 파일·학습 코드·행동 표의 해시가 바뀌면 기존 실험을 묵시적으로 재개하지 않는다. 수정된 실행기로 완료된 학습을 이어갈 때는 중단된 실험의 상태를 명시적으로 새 실험에 복사한다. 부모의 설정, 시드 진행, 가중치 경로, Adam 상태를 유지하고 새 실행 환경의 해시를 기록한다.

```powershell
& $racePython $raceTool init --work-dir debug_artifacts/commander/my_next_run `
  --resume-from debug_artifacts/commander/multirace_20260908/training_run/state.json
```

각 학습 묶음은 실제 종족, 정책 파일 해시, 정책 버전, 양쪽 종료 결과, 행동 마스크를 검증한다. 유효하지 않은 경기는 한 번 다시 수집하고 여전히 실패하면 갱신을 중단한다. 채택된 학습 RLO는 갱신 후 제거하며 `--keep-rollouts`로 유지할 수 있다. 평가 로그, 경기 보고서, 리플레이, 모델별 학습 지표는 보존한다.

## 구현 계약

- 원본 TRC와 기존 생산·건설·연구 검증 명세에서 `ranker_commander_catalog.py`가 `commander_races.json`과 `ranker_ai_commander_races.h`를 생성한다. 실전에서 건설할 수 없는 공용 검증용 생산 건물은 제외한다.
- 관측 606 → 642: 자기 종족 one-hot 4개, 소유 특수 유닛 16개, 생산 대기 특수 유닛 16개를 추가했다. 적 유닛의 기존 32칸 통계는 기존 상대 인덱스를 유지한다.
- 행동 크기 `(64,16,4,8,16,3,3,3)`, 총 117 logits. 가중치 schema `0xB32DB21E`, RLO 형식 5, 레코드 4521바이트다.
- 기존 528/542/606 가중치는 명시적 전이로만 확장한다. 기존 RLO는 과거 분석용으로 읽을 수 있지만 새 관측을 대신해 학습에 사용하지 않는다.
- `-AIOWNTRIBE:N`은 첫 정책, `-AIOWNTRIBE2:N`은 두 번째 정책의 종족이다. 기본값은 모두 2다. `-AITRIBE:N`은 기본 AI 상대 종족이다. 정책 간 대전에는 `-AIVS`와 `-AIWEIGHTS2`를 사용한다.
- 원시인 일꾼 타입 0과 빈 생산 대기열을 구분하고, 엘프 건설의 이동·생성 상태를 추적한다. 데몬 BoneFighter `0x5a`는 Devil `0x3a`와 소유 병력 통계에서 구별한다. 합체 행동은 티라노에만 허용한다.

## 검증과 초기 결과

관련 C++ 회귀 검사 7개와 Python 검사 88개를 통과했다. 가중치/Adam 전이, 과거 로그 읽기, 현재 추론·학습, 종족 검증, 시드 전달, 자기대전 배정과 전환 기준을 검사했다.

네 종족과 종족 간 대전의 6000프레임 실행 검사에서 유효한 종료 로그와 양쪽 종족을 확인했다. 엘프 건설 수정 후 8경기에서 양쪽의 금지 행동 선택과 명령 미실행 기록은 모두 0이었다. C++/Python 무작위 입력 추론 비교의 최대 logit 오차는 `6.71e-8`이었다.

최종 실행 파일에서도 원시인→엘프→티라노→데몬→원시인 조합의 4경기를 다시 검사했다. 양쪽 8개 정책 로그가 모두 유효했고 금지 행동 선택 및 명령 미실행 기록이 0이었다. 엘프의 실제 학습 완료 버전 1과 다른 종족의 버전 0을 함께 실행해 서로 다른 버전의 대전도 확인했다.

별도 자기대전 갱신 검사에서는 종족마다 플레이어 1·2의 실제 로그를 함께 사용했다. 총 2108개 결정에서 정책의 행동 가중치가 갱신되고 체크포인트와 Adam 상태가 다시 로드됨을 확인했다. 네 종족의 기록된 행동 로그 확률을 Python에서 재계산한 최대 오차는 `3.58e-6`이었다. 이 짧은 검사는 실력 평가가 아니다.

첫 엘프 적응 회차는 실제 12경기, 17033개 결정으로 완료되었다. 1승, 금지 행동 선택 0건, 명령 미실행 0건이며 가치망만 갱신했다. 초기 실력은 아직 낮다. 이 체크포인트는 `training` 폴더에 보존했고, 관측 보완 후의 `training_run` 실험이 부모 상태를 기록하여 이어받는다. 현재 학습 및 자기대전 전환 여부는 앞의 `state.json`을 기준으로 확인한다.

검증 산출물은 `debug_artifacts/commander/multirace_20260908` 아래의 `smoke_games_fixed/manifest.json`, `smoke_games_final/manifest.json`, `selfplay_update_probe/summary.json` 및 테스트 로그에 있다.
