# 4종족 공격 이동과 PPO 후속 실험

사용자가 엘프·원시인·티라노·데몬 모두 공격 도중 돌아왔다가 다시 나아가는 모습을 확인했다.
공통 Commander 실행기의 집결 동작을 수정하고 동일 가중치 전후 비교 후 학습을 이어간다.

## 원인과 변경

기존에는 부대 중심과 거리가 384를 넘으면 앞선 유닛도 중심으로 MOVE했다.
192 이내로 다시 모인 뒤에도 기존 intent serial의 실행 완료 표시가 남아 있어,
현재 MOVE가 끝날 때까지 원래 공격을 재개하지 않는 경로가 있었다.

- 공격·공성·견제·사냥 이동에서 앞선 유닛은 제자리 HOLD로 기다린다.
- 뒤처진 유닛은 중심으로 합류한다. 언덕에서는 BFS 경로 전체에서 가장 가까운 지점을
  찾아 진행 정도를 확인한다. 이미 굽이를 지난 선두를 초반 경로 방향만 보고 불러오지 않는다.
- 한 번의 기다림은 최대 128 프레임, 재출발 후에는 최소 64 프레임 진행한다.
  길에 막힌 유닛이나 새 증원 때문에 무한히 대기하지 않도록 한다.
- 집결 종료 후 공격을 즉시 재개한다. 교전 반응, 명시적 철수, 정찰과 방어 위치 복귀는 유지한다.
- 새 `cohesion_resume_frame`은 실행기 내부 상태다. 관측/액션의 크기와 모델 형식은 바꾸지 않는다.
  해당 구조를 사용하는 Commander와 frontend를 함께 다시 빌드했다.

후진 명령과 집결 대기 진단을 로그에 남긴다. `march-backtrack`은 최종 목표 반대 방향으로
64 이상 이동을 명령한 경우이며 실제 이동 거리 측정값은 아니다. 언덕을 우회하거나
부상병이 후퇴하는 경우도 포함될 수 있으므로 모두 잘못된 명령이라고 해석하지 않는다.

## 직접 관련 검증

`ai_commander_march_regression`은 4종족 선두 대기/합류 후 재출발, 실제 게임의
`PlanAiSemanticActionV1` 검증과 HOLD 패킷 좌표, 대기 상한,
경로 중간 목적지와 대기 간격, 뒤처진 유닛의 합류, 교전 반응, 철수,
방어 위치 유지, 정찰, 패킷 한도 및 거절 후 재시도를 검사한다.
추가로 기존 Commander 검사에서 이번 변경과 직접 관련된 6개 함수를 전후 실행했다.

속도 6인 유닛 하나와 속도 3인 유닛 둘의 통제된 이동 재현에서 다음 결과를 얻었다.
네 종족 모두 같은 조건으로 검사했다. 실제 경기의 승률이나 종족별 원래 유닛 속도 실험은 아니다.

| 측정 | 수정 전 | 수정 후 |
|---|---:|---:|
| 합산 후진 거리 | 2,451 | 0 |
| 마지막 유닛 도착까지 프레임 | 1,952 | 1,928 |
| 최대 선두/후미 간격 | 600 | 600 |

처음 시도한 대기 간격은 최대 간격을 895까지 늘렸으므로 사용하지 않았다.
전체 기존 Commander 검사에는 변경 전부터 Meteo 표적 검사 실패가 있었다.
이번 이동 변경으로 고치거나 통과했다고 주장하지 않으며, 직접 관련 검사만 별도로 검증했다.

## 실험과 자료 검증

최초 실전 코호트 254는 HOLD에 의미적 좌표를 넣어 native 검증기가 거절하는
결함을 발견해 중단했다. 완료 10경기만 보관하고 미완료 경기는 평가/학습에서 제외했다.
원시인 대조군 4승, 후보 2승 2패, 엘프는 양쪽 1승이었다. 이 실행기로 PPO를 갱신하지 않았다.
모의 validator에서 빠진 계약을 실제 패킷 planner 검사로 보완했다.
HOLD 의미적 액션의 좌표는 0이고, 실제 정지 좌표는 planner가 live unit에서 구한다.

최초 실험: `debug_artifacts/commander/march_cohesion_20260911`.
수정 후 실험: `debug_artifacts/commander/march_cohesion_v2_20260911`.
언덕 보완 후 최종 학습 실험: `debug_artifacts/commander/march_cohesion_v3_20260911`.

코호트 255(v2 전후 32경기)는 양쪽 13/16승이며 집결 후진 명령이
90,217에서 16,070으로 감소했다. 종족별 승수는 원시인 4→3, 엘프 3→3,
티라노 3→4, 데몬 3→3이었다. 실제 리플레이의 HOLD 패킷 12,214개가 로그와 일치했다.
이 단계에서도 PPO를 갱신하지 않고 남은 언덕 집결 문제를 먼저 보완했다.

v3의 언덕 재현 검사는 v2 소스에서 실패하고 v3에서 통과했다.
직선 이동 재현의 최대 간격 600과 후진 거리 0도 유지했다.
v3는 같은 대조 실행기와 완료된 대조군 16경기를 재사용하고 후보 16경기만 새로 실행한다.
Commander 구현 외 312개 소스 파일과 헤더의 동일성을 확인했고,
대조군 가중치·정책 시드·맵·실행 파일 해시는 바꾸지 않았다.

코호트 256(v3)은 실제 신규 16경기와 위 대조 16경기를 비교했다.

| 종족 | 대조 → v3 승수(각 4경기) | 집결 후진 명령 전 → 후 |
|---|---:|---:|
| 원시인 | 4 → 4 | 22,493 → 41 |
| 엘프 | 3 → 3 | 24,738 → 298 |
| 티라노 | 3 → 2 | 8,432 → 68 |
| 데몬 | 3 → 4 | 34,554 → 443 |

합계는 양쪽 13/16승이다. 집결 후진 명령 90,217→850(99.1% 감소),
전체 공격 의도 중 후진 명령 97,681→2,738(97.2% 감소)이다.
실제 HOLD 패킷 25,261개가 진단 로그와 정확히 일치했다. 마스크 위반은 0이다.
전후 모두 승리한 원시인 대 티라노 조건의 종료 프레임은 23,836→15,020,
엘프 대 티라노 조건은 18,401→14,733이었다. 이는 해당 경기 종료 시점 비교이며
모든 경기의 이동 시간 개선을 뜻하지 않는다. 티라노 대 엘프 조건은 승리에서 패배로 바뀌었다.
이동 개선을 승률 향상과 동일시하지 않고 새 환경의 PPO 자료로 후속 학습한다.
`build.json`은 공통 객체로 링크한 수정 전/후 실행 파일과 소스·검사 결과를 고정한다.
기존 frozen 학습 실행기나 선택 모델을 덮어쓰지 않는다.

1. 같은 PPO 가중치(v220~223), 맵과 정책 시드로 전후 비교 32경기.
   종족별 상대 4종족을 한 번씩 만나므로 실행기마다 4경기다. 48경기 승률 평가가 아니다.
2. 수정 실행기로 새 학습 40경기: 현재 모델끼리 16, 과거 모델 상대 16, 내장 AI 상대 8.
   실제 자기대전과 내장 AI를 구분하고, 같은 경기 양쪽 자료를 독립 경기로 세지 않는다.
3. 각 종족의 정확한 현재 가중치 경험 14개만 사용해 PPO 2 epoch, 학습률 3e-6.
   전투 출력과 critic을 갱신하고 경제 출력·공유 특징·prefix embedding은 고정한다.
   native log probability/value 일치, 가중치 해시, 양쪽 종족/소유자/종료 상태를 검사한다.
4. 같은 수정 실행기에서 학습 전후 고정 16경기 비교. KL ≤ 0.02,
   clip fraction ≤ 0.1 사전 검사를 통과해야 경기 평가한다.

자료와 가중치 확인을 마친 각 코호트는 이 채팅에 보고한 다음 ACK한다.
완료 결과는 실험 종료 시 이 문서와 `completion.json`에 기록한다.

## 첫 PPO 후속 결과

코호트 257: 새 40경기에서 69,468개 행동, 종족별 14개 학습 관점의 기록을 확보했다.
시간초과는 실제 2경기이며 승리로 세지 않았다. 원시인/엘프/티라노/데몬 순으로
사냥 선택은 8/573/49/23회였다. 수집 리플레이의 HOLD 패킷 56,603개가 진단과 일치했다.

코호트 258: v250~253을 실제 PPO 2 epoch로 갱신했다. 행동 확률 최대 오차는
7.87e-6, value 최대 오차는 2.51e-6 이하였다. 고정한 가중치 및 같은 prefix에서의
보호 출력은 정확히 보존됐고, 전투 actor 가중치는 변경됐다. 네 모델 모두 사전 검사를 통과했다.

코호트 259: 같은 실행기에서 갱신 전후 각 종족 4경기를 비교했다.
원시인 4→4, 엘프 3→3, 티라노 2→2, 데몬 4→3승이었다.
데몬은 이 평가에서 더 나았던 갱신 전 v223을 실험의 다음 출발점으로 유지한다.
원시인/엘프/티라노의 다음 출발점은 v250/251/252이며 기존 정식 최상 모델은 교체하지 않는다.
이동 개선과 추가 PPO의 승수 개선을 구분해야 하며, 첫 PPO의 추가 승수 개선은 확인되지 않았다.

한 시간초과 경기에서는 원시인 MAIN 14기와 선택 가능한 MAIN 명령이 남았으나
HOLD를 유지했다. 후반 임무 선택 문제는 해결됐다고 주장하지 않는다.
학습 자료에 있던 이 상황의 MAIN 선택 확률은 9.19%→9.27%로만 바뀌었으며,
이는 훈련 문맥에서의 진단값이고 실제 후반 정리 성공의 증거가 아니다.
## 티라노 출발점 재검사와 두 번째 PPO

코호트 260: 원래 v23과 전투 actor 텐서가 정확히 같은 critic 보정본 v212를
같은 v3 실행기와 고정 4조건에서 검사했다. 원시인/엘프/데몬 상대로 승리하고
티라노 상대로 패배해 3/4승이었다. 직전 v252의 2/4승보다 나았으므로
두 번째 실험의 출발점은 원시인 v250, 엘프 v251, 티라노 v212, 데몬 v223이다.
이는 개발 조건에 따른 출발점 선정이며 정식 최상 모델 승격이 아니다.

두 번째 실험은 `debug_artifacts/commander/march_ppo_cycle2_20260911`에 보존한다.
새 40경기를 수집하고 PPO 3 epoch, 학습률 1e-5로 갱신한 뒤 같은 4조건씩 비교한다.
경제 출력과 공유 특징을 고정하고, 현재 가중치가 직접 생성한 자료만 사용하는 계약은 유지한다.
각 종족의 비교 기준 자료가 선정한 가중치의 해시와 일치함을 수집 전에 확인했다.

v3 실행기 전후 모두 승리한 12조건에서 평균 종료 프레임은
18,776.42→17,461.25로 약 7.0% 감소했고, 그중 7조건이 빨라졌다.
이는 공통 승리 조건의 전체 경기 시간이며 순수 이동 시간이나 전체 조건의 평균이 아니다.
근거는 v3의 `matched_win_duration.json`이다.

코호트 261: 새 40경기에서 65,262개 행동을 확보했다. 종족별 14개 학습 기록의
승/패는 원시인 10/4, 엘프 10/4, 티라노 3/11, 데몬 8/6이었다.
이는 현재/과거 정책 및 내장 AI를 섞은 상대와 양쪽 소유자 관점이 포함된 수치다.
시간초과와 마스크 위반은 0이고, 실행 중 무응답 거절은 원시인/티라노 각 2회였다.
사냥 선택은 원시인 22, 엘프 639, 티라노 21, 데몬 18회였다.
티라노의 12개 신경망 상대 기록은 1승 11패, 내장 AI 상대 2기록은 2승이었다.
자기대전에서 강하다고 주장할 수 없으며, 내장 AI 선별과 별도로 약점을 확인해야 한다.

코호트 262: v260~263으로 각 3 epoch PPO를 실행했다. 실제 전투 actor 변경,
보호 파라미터와 동일 prefix의 보호 출력 보존, 내보낸 가중치의 재적재 일치를 검사했다.
게임/학습기의 log probability 최대 오차는 8.11e-6, value 최대 오차는 2.27e-6 이하다.
갱신 후 최대 KL은 0.000546, clip fraction은 0.003341 이하였다.
모두 사전 검사를 통과했지만 실제 승수 향상 여부는 별도 경기 평가로 판단한다.

코호트 263: 두 번째 PPO도 같은 4조건씩 평가했다.

| 종족 | 갱신 전→후 승수 | 후속 학습 출발점 |
|---|---:|---|
| 원시인 | 4→3 | 이전 v250 유지 |
| 엘프 | 3→3 | 새 v261 |
| 티라노 | 3→2 | 이전 v212 유지 |
| 데몬 | 4→2 | 이전 v223 유지 |

엘프의 집결 중 후퇴 명령은 162→96회였지만, 모든 공격 의도의 후퇴 명령은
459→515회였다. 후자는 지형 우회와 전술적인 후퇴도 포함하며 전체 행동이 모두 개선됐다는 뜻은 아니다.
평가 시간초과, 무응답 거절, 마스크 위반은 모두 0이었다.
실제 리플레이와 대기 진단이 정확히 일치했다: 수집 40경기 64,020개,
평가 16경기 14,226개. 패킷 증거는 두 번째 실험의 `packet_evidence.json`이다.

이번 수정 후 실제 학습 80경기(신경망 대전 64, 내장 AI 상대 16)에서
134,730개 행동으로 각 종족의 PPO 갱신을 두 차례 실행했다.
승수가 떨어진 갱신본은 후속 출발점에서 제외했고, 두 차례 PPO 자체의 추가 승수 향상은
확인하지 못했다. 선정한 네 출발점의 개발 성적은 합산 14/16이지만 이는 모델을 선정한
동일 조건의 성적이며 독립 검증이나 48경기 승률이 아니다.
이전에 검증한 최상 모델과 frozen 실행 파일은 보존했다.

후속 학습 출발점과 수정 실행기의 정확한 경로·해시는
`debug_artifacts/commander/race_strength_20260909/training_run/march_continuation_20260911.json`에 보존한다.
이 상태에서 실행 중인 학습/평가 프로세스는 없다. 이후에는 이 레지스트리의 모델과 실행기를
사용해 새 경험을 수집해야 하며, 탈락한 최신 파일을 날짜만 보고 선택해서는 안 된다.

집결 실행기의 후퇴 외에 정책이 공격·사냥에서 HOLD/방어/철수로 임무를 바꾸는 선택도
남아 있다. 두 번째 평가에서 본진 512 이상 거리, 평균 체력 75% 이상,
관측된 본진/주변 위협 없음, 자동 철수 아님으로 선별한 전환은
원시인/엘프/티라노/데몬에서 각각 20/6/5/24회였다.
이는 모델의 임무 선택 기록이며 실제 이동량이나 부당한 철수의 확정 판정이 아니다.
보이지 않는 적과 손실·증원 판단도 확인해야 한다. `screen_recall_review.json`에 사례를 남겼다.

다음 개선에서는 이 임무 전환과 후반 HOLD로 경기를 끝내지 못한 사례를 먼저 비교하고,
티라노의 자기대전 패배에서 공격 출발·병력 소모·본진 방어를 확인해야 한다.
사전 손실 감소만으로 채택하지 말고, 원인별 비교와 새 실제 경기 성적으로 채택한다.

루트 `play_last_replay.cmd`는 가장 최근 완료된 경기 기록을 선택한다.
탈락한 평가 모델의 패배 경기도 최신 경기라면 표시되며 최상 모델의 대표 경기라는 뜻은 아니다.
기록된 신경망 소유자는 리플레이 명령을 사용하고 해당 소유자의 내장 AI는 비활성화한다.
내장 AI 상대는 기존 내장 AI로 재생한다. 이번에는 뷰어 해시와 명령의 dry-run을 확인하며,
GUI로 전체 리플레이를 재생해 동기화 동등성까지 검사한 것은 아니다.
