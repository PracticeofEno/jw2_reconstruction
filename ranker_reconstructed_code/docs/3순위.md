# 3순위 — 네트워크 구조 개편: 그리드 CNN + 시간 기억(GRU) + v8 동시 전환

관련 문서: `1순위.md`(액션 66 + 64-way 타깃 헤드), `2순위.md`(feature ~773, 그리드 9채널).
이 세 문서는 **하나의 v8 계약**이다 — 체크포인트 무효화를 1회로 만들기 위해 반드시 같은
재학습 사이클에 묶는다.

## 0. 현황

`ranker_ppo.py:46-86` `ActorCritic`:

- **완전 분리 2탑**: `policy_net`, `value_net` 각각 `Linear(545,256)→Tanh→Linear(256,256)
  →Tanh→헤드`. (분리는 BC 웜스타트 보호를 위한 의도적 설계 — 유지한다.)
- **545차원을 통짜 flat**으로 소비. 8×8×6 그리드([86..469], 384차원)에 공간 구조 처리 없음
  (Conv/reshape 전무).
- **기억 없음**: LSTM/GRU/frame-stack/액션 히스토리 없음. 완전 반응형 단일 스텝 정책.
- BC 웜스타트(`bc_pretrain`, :139-166)도 같은 구조를 학습. 체크포인트는 자기 서술적
  (`_hidden_of`, `_check_checkpoint_shape`)이라 구조 확장 시 로드 가드가 이미 있다.

문제:

1. flat MLP는 그리드의 인접성(적이 "옆 셀"에 있다)을 쓰지 못한다. 2순위에서 채널이
   6→9로 늘면(576차원) 이 낭비가 더 커진다.
2. fog-정직 오버홀 이후 관측은 진짜 부분관측(POMDP)이 됐다. 반응형 정책은 "방금 정찰로
   본 적 조성", "직전에 내가 무슨 명령을 내렸는지"를 다음 결정에서 모른다. 2순위의 C++
   기억(적 건물/군대)이 가장 중요한 부분을 메워주지만, 그 밖의 시간 패턴(교전 흐름,
   자원 추세, 자기 행동 이력)은 네트워크 기억이 필요하다.

## 1. 그리드 CNN

### 1.1 구조 (권장)

입력 분해: `x_grid` = feature[86..469] + v8 신규 채널(2순위) → **(C=9, 8, 8)**로 reshape,
`x_scalar` = 나머지 전부 (v8 기준 약 197차원).

```
grid:   Conv2d(9,16,3,pad=1) → Tanh → Conv2d(16,32,3,pad=1) → Tanh → flatten (2048)
        → Linear(2048,128) → Tanh                                # grid embed 128
scalar: Linear(~197,128) → Tanh                                  # scalar embed 128
trunk:  concat(256) → Linear(256,256) → Tanh                     # (policy/value 각자 보유)
heads:  policy → logits_action[66], logits_target[64] (1순위 §2.3)
        value  → 1
```

- 8×8은 작아서 conv 비용이 무시할 수준 (CPU 인퍼런스 sub-ms 유지 — IPC 경로 영향 없음).
- **채널 순서 주의**: C++ 인코더의 그리드 기록 순서(채널-major인지 셀-major인지,
  ranker_ai_rl_features.cpp:622-629 부근)를 확인하고 reshape 축을 맞춘다. 순서가
  셀-major(x,y별 6채널 연속)라면 `view(8,8,C).permute(2,0,1)`. **reshape 축이 어긋나도
  학습은 "돌아가기 때문에" 조용히 성능만 깎인다 — 단위 테스트 필수**: C++에서 특정 셀
  하나에만 값을 넣은 인코딩을 Python에서 reshape해 같은 (c,y,x)에 오는지 검사.
- policy/value 2탑 분리는 유지하되, **그리드 conv를 공유할지**는 열린 선택이다. 분리
  원칙(가치 그래디언트가 정책 표현을 흔들지 않게)을 지키려면 conv도 각자 소유가 안전하다.
  파라미터 2배는 이 규모에서 문제가 아니다. → **각자 소유 권장**.

### 1.2 BC/체크포인트 영향

- `bc_pretrain`은 구조만 새 클래스로 바뀌고 손실/가중치 로직은 그대로.
- `_check_checkpoint_shape`는 conv 도입 후 layer-0 기반 폭 추론(`_hidden_of`)이 깨지므로,
  체크포인트에 **명시적 메타(`{"version":8,"n_features":…,"n_actions":66,"arch":"cnn"}`)를
  저장**하고 로드 시 하드 에러로 검사하는 방식으로 교체한다 (기존 정신 유지, 구현만 교체).

## 2. 시간 기억

### 2.1 단계적 도입 (권장 순서)

**2-a. 액션 히스토리 + 프레임 스택 (v8에 즉시 포함, 저비용)**

- 입력에 **직전 K=4 결정의 액션 one-hot**(4×66)과 **직전 관측과의 스칼라 델타**
  (핵심 스칼라 ~20개의 Δ: 자원, 아군/적 카운트, 전력비)를 붙인다.
- 구현이 사소하다: IPC 서버/rollout 쪽에서 이전 스텝을 들고 있다가 이어붙이면 되고
  (C++ 변경 불필요 — Python 측 래핑), 에피소드 JSONL은 이미 시퀀스라 오프라인 재구성 가능.
- 반응형 정책의 최대 약점 두 가지(직전 행동 기억, 추세)를 GRU 없이 60% 해결한다.
- **8프레임 요동 문제에 직접 효과**: "방금 attack을 골랐다"가 입력에 있으면 목표를
  유지하는 정책을 표현할 수 있다 (현재는 같은 상태 → 같은 분포 → 독립 재샘플링이 요동의
  구조적 원인. 메모리의 미결 항목 "부대 목표 8프레임 요동"의 근본 대응이기도 하다).

**2-b. GRU (2-a로 부족이 확인되면)**

- trunk 뒤에 `GRU(256, 128)` 1층. 정책/가치 각자 소유(분리 원칙 동일).
- 학습 변경(이것이 비용의 본체):
  - rollout에 hidden state 저장, 게임(에피소드) 경계에서 reset.
  - PPO 미니배치를 **시퀀스 청크**(예: 길이 32, truncated BPTT)로 재구성 — 현재의
    셔플-flat 미니배치(:620-621)를 청크 셔플로 교체.
  - 서빙(`ranker_ipc_server.py`): 커넥션별·owner별 hidden state 보관, `{"t":"end"}`에서
    reset. `-AIVS`는 두 owner가 한 커넥션으로 오므로 **owner 키 분리 필수**.
  - eval/league/selfplay의 `_load_policy` 경유 체인 전부 hidden 전달 대응.
- 판단 기준: 2-a 적용 후에도 (i) 요동 병리가 남거나 (ii) 정찰 정보를 수 결정 뒤에 활용하지
  못하는 증거(정찰 직후와 30스텝 후의 행동 분포가 동일)가 보이면 도입한다.

### 2.2 넣지 않는 것

- LSTM(GRU 대비 이득 없음), attention/transformer(현 데이터 규모에 과설계),
  프레임 단위 스택(결정 단위 8프레임 스택이면 충분).

## 3. 함께 정리하는 학습 세부 (구조 개편에 부수)

구조가 바뀌어 어차피 전 체크포인트가 무효가 되는 시점이므로, 같은 커밋에서 처리하면
공짜인 것들 (모두 `ranker_ppo.py` 소규모 수정):

1. **value clipping**: 현재 plain `mse_loss`(:630) — PPO 표준 clipped value loss로.
   가치망이 한 업데이트에 과도하게 이동하는 것을 막는다.
2. **LR decay**: iters에 걸친 linear decay (3e-4→1e-4, 자가대전은 1e-4→3e-5).
3. **best-checkpoint 자동 보존**: 이미 한 번 최적 체크포인트를 유실했다(30-iter 8.2
   overwrite 사고). 게이트/eval 점수 기준 `*.best.pt` 자동 유지.
4. **관측 정규화는 추가하지 않는다**: C++ 인코더가 v3부터 [0,1] clamp 정규화를 보장하므로
   running mean/std는 불필요 복잡도 + 결정론(재현성) 훼손. 현행 유지가 맞다.

(상대 풀/PFSP는 4순위로 이번 채택 범위 밖 — 단, 구조 개편과 독립적이라 나중에 체크포인트
무효화 없이 추가 가능하다는 점만 기록해 둔다.)

## 4. v8 전환 절차 (세 문서 통합 실행 순서)

1. **C++ v8**: 1순위(raid 그룹, 타깃 헤드 계약, IPC 확장) + 2순위(관측/인코더/기억)
   → 회귀 전부 통과, `-AIRANDOM` 스모크(신규 액션·셀 타깃 실행 실패 0 근접, 같은 시드
   byte-identical).
2. **Python v8**: rl_env/imitation 상수 동기화, CNN 2탑 + 2헤드 + 액션 히스토리(2-a),
   체크포인트 메타 가드, 그리드 reshape 단위 테스트, §3 항목.
3. **데이터**: 인간 리플레이(패킷 라벨 — 공격 좌표 포함) + 내장 AI 관찰 재수집 → v8
   데이터셋 → BC.
4. **베이스라인 고정**: BC(v8)를 `ranker_eval.py`(다중 시드 대역, stochastic)로 측정 —
   이후 모든 비교의 기준점.
5. **자가대전 리그** 재가동 (BC 초기화). 관찰 지표: raid/타깃 셀 사용률, 게이트 승격률,
   섬멸 비율, (2-a 효과) 목표 전환 빈도 감소.
6. GRU(2-b)는 5의 증거를 보고 별도 결정 — 이것만은 체크포인트 무효화 없이 추가 불가하므로
   (입력이 아니라 코어 구조), 도입한다면 v8 초기에 몰아서 하는 것이 이상적이다. 판단이
   서지 않으면 v8에서 GRU를 **처음부터 켜고** 2-a와 병행하는 것도 방어 가능한 선택이다
   (비용은 PPO 시퀀스 배치 구현뿐, 성능 하방 리스크는 작다).

## 5. 리스크

- **conv reshape 축 불일치** — §1.1의 단위 테스트로 차단 (조용한 성능 저하 유형).
- **GRU + 결정론**: hidden state는 float 누적이라 같은 시드 재현이 스텝 순서에 민감해진다.
  워커 병렬에서는 게임별 독립 hidden이므로 문제없지만, 게임 내 재현 검증은 argmax 단일
  게임으로 수행한다.
- **BC 데이터의 히스토리 필드**: 2-a의 액션 히스토리는 모방 데이터에도 있어야 한다
  (JSONL 시퀀스에서 재구성 가능 — 수집 형식 변경 불필요, 로더만 수정).
- 학습 시간: CNN+2헤드로 스텝당 연산 증가는 CPU에서 계측 필요. 게임 실행(~수십 초)이
  지배적이라 병목 이동 가능성은 낮다.
