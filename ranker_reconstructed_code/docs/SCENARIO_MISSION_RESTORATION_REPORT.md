# 종족별 시나리오 미션 복원 보고서

작성일: 2026-08-16

## 현재 결론

원시인, 티라노, 엘프, 데몬의 8개 미션씩 총 32개 시나리오를 원본 데이터에서 선택하고 실행할 수 있도록 복원했다. 종족 선택, 미션별 스토리 카드, 브리핑 화면과 동영상, 원본 맵 유닛, UMS 트리거, 승패 처리 및 다음 미션 진행 경로를 연결했다.

이번 복원에서 가장 큰 실행 오류는 캠페인 맵의 미션 번호 `0..7`을 일반 게임 모드로 잘못 해석한 것과, 원본 맵에 배치된 유닛을 지우고 일반 대전용 시작 유닛으로 교체한 것이었다. 캠페인 실행 중에는 미션 번호를 진행 상태로 별도 보존하고, 실제 게임 런타임은 원본과 같은 Use Map Setting 모드로 초기화하도록 수정했다. 또한 원본 record 7의 유닛과 건물을 유지한 채 플레이어·카메라·수명주기 집계만 초기화하는 전용 시작 경로를 추가했다.

## 원본 아카이브 대응

### 시나리오 맵

`Jw2_06.trc`는 종족별 12개 레코드 블록으로 구성된다. 각 블록의 앞 8개만 실제 미션이며 뒤 4개는 플레이 가능한 TRC가 아니다.

| 화면 종족 | 내부 종족 열 | 미션 레코드 |
|---|---:|---:|
| 원시인 | 0 | 0–7 |
| 엘프 | 1 | 12–19 |
| 티라노 | 2 | 24–31 |
| 데몬 | 3 | 36–43 |

화면 표시 순서는 원시인, 티라노, 엘프, 데몬이지만 원본 아카이브의 내부 열은 원시인, 엘프, 티라노, 데몬 순서다. 이 차이를 원본의 선택 명령과 동일하게 매핑했다.

### 미션 브리핑

`Jw2_04.trc`는 미션 우선 배열이다. 사용 레코드는 `미션 * 0x50 + 종족 * 0x14`로 계산한다. 32개 브리핑에는 각각 좌우 2개 Bink 영상이 있어 총 64개 영상이 필요하다. 원본 영상을 내장 MP4 팩으로 변환해 Bink 런타임이 없는 환경에서도 원본 위치와 크기로 재생되도록 했다.

### 시작·스토리·엔딩 영상

`Jw2_08.trc`에서 확인한 대응은 다음과 같다.

| 레코드 | 용도 |
|---:|---|
| 0–3 | 종족 시작 영상 |
| 4–12 | 특정 미션의 한 프레임 스토리 카드 |
| 13 | 원시인 엔딩 |
| 14 | 엘프 엔딩 |
| 15 | 티라노 엔딩 |
| 16 | 데몬 엔딩 |

한 프레임 스토리 카드는 재생 즉시 사라지지 않고 원본처럼 입력할 때까지 유지한다. 스토리 카드에서 브리핑 화면으로 넘어갈 때 같은 입력이 게임 시작 버튼까지 관통하지 않도록 입력 상태도 초기화한다.

## 32개 미션 정적 검사

각 맵에서 확인한 값은 `활성 오브젝트 / 로컬 소유 오브젝트 / 트리거 수 / 승리 명령 수 / 패배 명령 수`이다. 모든 승리·패배 트리거가 참조하는 그룹은 초기 맵에서 실제 오브젝트를 갖고 있음을 별도로 확인했다.

| 종족 | M1 | M2 | M3 | M4 | M5 | M6 | M7 | M8 |
|---|---|---|---|---|---|---|---|---|
| 원시인 | 246/25/74/1/3 | 285/61/76/1/3 | 252/24/64/1/2 | 454/31/62/2/3 | 436/54/98/1/4 | 358/52/85/1/2 | 622/20/81/1/3 | 400/51/87/1/2 |
| 티라노 | 230/10/132/1/1 | 507/24/65/1/2 | 399/1/64/1/1 | 267/29/58/1/1 | 347/14/39/1/2 | 294/60/97/1/10 | 478/53/39/1/3 | 303/8/72/1/2 |
| 엘프 | 193/4/51/1/2 | 320/28/66/2/0 | 352/68/65/2/2 | 327/50/70/1/3 | 347/36/96/1/2 | 422/23/80/1/1 | 400/22/97/1/1 | 641/163/118/1/5 |
| 데몬 | 191/12/52/1/1 | 339/70/51/1/1 | 416/29/51/1/1 | 272/29/70/2/1 | 345/30/65/1/1 | 429/37/35/1/1 | 547/23/100/1/1 | 507/25/87/1/2 |

추가로 32개 맵 모두 내부 미션 번호가 `0..7`로 정상 저장되어 있고, 레코드 5의 트리거와 레코드 7의 유닛 데이터가 존재하는 것을 확인했다.

릴리스 빌드 후 `ctest --test-dir build_note2_release --output-on-failure`를 실행했으며 기존 회귀 테스트 19개가 모두 통과했다. 수송, 녹셔스, 혼합 유닛 스킬, UMS 종료 조건, 선택 처리, 네트워크 및 리플레이 테스트를 포함한다.

## 변경한 핵심 동작

- 캠페인 미션 번호와 게임 런타임 모드를 분리했다.
- 캠페인은 원본처럼 UMS 트리거와 오브젝트 그룹을 활성화한다.
- 원본 맵의 활성 유닛·건물을 일반 대전용 6개 시작 유닛으로 교체하지 않는다.
- 캠페인 유닛을 기준으로 소유자별 인구, 유닛·건물 수 및 점수를 다시 집계한다.
- 스크립트 전용 소유자의 유닛 때문에 비활성 플레이어 슬롯이 임의로 활성화되지 않게 했다.
- 1장의 미션 번호 0을 미설정 값으로 오인하지 않도록 승리·패배 진행 계산을 수정했다.
- 8장 종료 시 종족별 엔딩 레코드를 선택하도록 현재 미션 번호를 영상 정책에 전달한다.
- 32개 브리핑의 두 영상과 `Jw2_08.trc` 레코드 4–16을 실행 파일 리소스로 추가했다.

## 아직 필요한 실플레이 확인

32개 맵의 데이터와 결과 트리거는 전부 검사했지만, 각 미션을 사람이 처음부터 승리 조건까지 완주하는 총 32회 장시간 플레이는 이번 자동 통합 검증에 포함하지 않았다. 따라서 미션 중후반의 복합 AI 행동, 대화 타이밍, 특정 이벤트 연출은 실제 플레이 피드백이 생기면 해당 미션과 트리거 번호를 기준으로 원본과 추가 대조해야 한다.

현재 배포 대상은 `RankerOCPV_Win/ranker_rebuild.exe`이며 원본 `RankerOCPV_Win/ranker.exe`는 변경하지 않았다.
