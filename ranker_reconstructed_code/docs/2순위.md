# 2순위 — 관측 확장: 적 조성 상세화 + 지형 채널

관련 문서: `1순위.md`(액션 확장 — 같은 v8 계약으로 묶는다), `3순위.md`(네트워크 — 그리드
채널이 늘면 CNN의 가치가 함께 커진다), `AI_PLAY_OBSERVATION_V4_PROPOSAL.md`(fog-정직 원칙).

## 0. 원칙 (기존 결정 유지)

- **fog-정직**: 새 feature는 전부 "현재 시야에서 보이는 것 + 자기 자신이 과거에 본 것의
  기억"으로만 만든다. 적 업그레이드/생산 상태 같은 비공개 정보는 넣지 않는다
  (ranker_ai_observation.h:114-117의 설계 그대로).
- **append-only**: 기존 인덱스 [0..544]는 절대 재배치하지 않는다. v8은 [545..]에 덧붙인다.
- 보상 전용 특권 정보(war-score 손실 회계)는 계속 관측 밖에 둔다.

## 1. 적 조성 상세화

### 1.1 현황과 문제

현재 적 관련 feature (ranker_ai_rl_features.cpp):

- [31..35] 가시 적 mobile/건물/합계, 최근접 거리/유무.
- [487..497] 역할 4종(worker/melee/ranged/transport) 카운트, 지배 종족 one-hot,
  **적 체력 총합**, 건설중 수, 적 최대 사거리.
- 로컬 전력비 [81]도 **체력 기준**이다.

문제:

1. **카운터 판단 불가**: "원거리 12기"만 보이고 그것이 딜로포스인지 에그 스로워인지 모른다.
   유닛 상성(공중/지상, 사거리, 화력)에 따른 생산 대응을 학습할 근거가 없다.
2. **전력 평가가 체력 합**: 마소스 10기(HP 합 큼, 화력 낮음)와 트리세스 4기(HP 합 작음,
   화력 큼)를 구분 못 한다. force ratio가 실제 교전 결과와 어긋난다.
3. **적 군대의 "기억"이 없다**: 적 건물은 기억 채널이 있지만(그리드 채널 4 =
   visible+REMEMBERED), 적 군대는 시야에서 사라지는 순간 관측에서 소멸한다. fog-정직
   오버홀 이후 적 정보가 정말로 희소해졌으므로, "마지막으로 본 적 군대(위치·규모·시각)"
   기억이 없으면 정책은 방금 본 대군도 잊는다.

### 1.2 개선안

#### (A) 적 타입별 카운트 — 종족 상대 인덱스 16슬롯

전 종족 타입을 개별 슬롯으로 펼치면 4종족×~12타입으로 폭발한다. JW2의 타입 배치는
종족 대칭이다(worker = tribe·0x10, 유닛은 +0x0f까지, 건물은 0x60+tribe·0x10 — 메모리의
-AITRIBE 조사로 확인). 따라서:

- **슬롯 = `type_id & 0x0f`** (0..15), 종족은 이미 one-hot으로 있다([491..494] 부근).
- 신규 16 feature: 가시 적 mobile을 종족 상대 슬롯별 카운트/20으로 인코딩.
- 혼성(동맹 없는 FFA에서 두 종족 적이 동시에 보이는 경우)은 슬롯 합산 — 지배 종족
  one-hot과 함께 쓰면 대부분 구분된다. 정밀 구분은 과설계로 판단, 보류.
- 향후 종족 파라메트릭 통합 모델(메모리의 role-slot 집계 방향)과도 이 인덱싱이 호환된다.

#### (B) 화력 가중 전력 feature — 공격력 노출 (v8 관측의 핵심)

`AiObservedUnit`에는 **공격력(damage)과 무기 쿨다운이 없다** (사거리·체력·클래스만 있음,
ranker_ai_observation.h:97-182). 유닛 정의 테이블(`UnitMovementDefinition` — 비용/사거리를
이미 여기서 읽고 있다)에서 공격력을 찾아 관측에 넣는다:

- `AiObservedUnit.attack_damage` (+ 대공 별도값이 있으면 `attack_damage_vs_air`).
  정의 테이블에서 어느 필드가 공격력인지는 **원본 오디트가 선행 조건**이다 —
  `ai_techtree_audit.txt` 덤프를 확장해서 damage 후보 필드를 실측(교전 로그의 HP 감소량과
  대조)으로 확정한다. 티라노 근접 4종의 `action_range_base=50` 확인 때 쓴 방법 그대로.
- 신규 feature:
  - 아군: 근접/원거리 화력 합 (damage×count, 정규화) 2개, 대공 화력 유무 1개.
  - 적(가시): 동일 3개.
  - **화력 기준 전력비** 1개 — 기존 체력 기준 [81]은 유지(append-only), 새 전력비를 추가.
- 무기 쿨다운(발사 주기)은 정의 테이블에서 확정되면 같이 노출한다. 이것은 마이크로
  실행기의 카이팅(치고 빠지기) 전제 조건이기도 하다 — 실행기 개선은 이 문서 범위 밖이지만
  관측이 먼저 뚫려야 한다 (micro_executor 설계의 known gap).

#### (C) 적 군대 기억

적 건물 기억(`ai_play_enemy_building_memory`, 펌프에서 유지)과 같은 패턴으로:

- 펌프에 owner별 `enemy_army_memory`: 매 프레임, 가시 적 전투원의 (셀별 카운트, 관측
  프레임)을 기록. 가시 셀은 갱신(비었으면 소거 — razed-confirm과 같은 규칙), 비가시 셀은
  마지막 값 유지. **fog-정직**: 자기가 본 것의 기억일 뿐.
- 신규 feature:
  - 그리드 **채널 7 = 기억 속 적 군대** (8×8, 64개): 가시+기억 적 전투원 밀도.
  - 스칼라 4개: 마지막 적 군대 목격 후 경과 프레임(정규화), 목격 지점 dx/dy(정규화),
    목격 규모/20.
- 이것은 3순위의 GRU(시간 기억)와 역할이 겹치지만 상보적이다: C++ 기억은 정확하고 영구,
  GRU는 그 밖의 모든 시간 패턴용. C++ 쪽이 싸고 확실하므로 먼저 넣는다.

### 1.3 규모

(A) 16 + (B) 7 + (C) 64+4 = **+91 feature**. 지형(§2)과 합쳐 v8에서 545 → 약 700 수준.
flat MLP에는 부담이지만 3순위의 CNN 개편(그리드는 conv로 흡수)과 묶이면 문제없다.

## 2. 지형 채널

### 2.1 현황과 문제

- 8×8 그리드 6채널 [86..469]: 아군 건물/아군 군대/적 mobile/적 건물(가시+기억)/자원/
  탐사율 (ranker_ai_rl_features.cpp:622-629). **통행 가능성 채널이 없다.**
- v7 관측은 타일별 `passable`(엔진 클래스0 규칙)/`buildable`/`placement_class`를 이미
  수집한다 (ranker_ai_observation.h — v7 확장). 즉 데이터는 있는데 인코딩만 안 한다.
- 문제: 정책이 "이 방향은 못 지나간다(물/절벽)", "여기는 건설 가능 지대다"를 모른다.
  Python Jurassic 같은 맵에서 진입로(초크)가 승부를 가르는데, 현재 네트워크에는 맵이
  '탐사율 지도'로만 보인다. 확장 사이트 선택(ranker_ai_expansion)은 C++이 다 해주지만,
  공격 경로·방어 위치 판단은 정책 몫이고 근거가 없다.

### 2.2 개선안

- 그리드 **채널 8 = 통행 가능 비율**: 셀(16×16타일=256타일) 내 `passable` 타일 비율.
  정적 지형이므로 한 번 계산해 캐시 가능 (탐사 여부와 무관하게 공개해도 되는지는 결정
  필요 — 원본 게임은 맵 지형을 미니맵에서 공개하므로 **공개(fog 무관)가 원작 준수**.
  탐사 전 지형을 숨기는 것이 오히려 인위적이다).
- 그리드 **채널 9 = 건설 가능 비율**: 셀 내 `buildable` 비율. 확장/견제 위치 판단 보조.
- 스칼라(선택): 자기 시작 위치 기준 4방위 통행 가능 비율 4개 — 초크 방향의 저해상도 요약.
  CNN이 채널 8에서 스스로 뽑을 수 있으므로 3순위 채택 시 생략 가능.
- **해상도는 8×8 유지**. 16×16(=256셀×채널)으로 올리면 표현력은 늘지만 feature가
  채널당 256개씩 늘어난다. 8×8(셀=512px)로 시작하고, CNN 도입 후 병목이 확인되면
  그때 16×16으로 올리는 것이 증분적이다 — 해상도 변경도 계약 무효화이므로 v8에 넣을지
  여부는 3순위 구현과 같은 시점에 한 번만 결정한다.

### 2.3 규모

채널 2개 = +128 feature (8×8 기준).

## 3. 계약 정리 (v8 체크리스트)

이 문서와 1순위를 합친 v8 계약 변경점:

| 항목 | v7 | v8 |
|---|---|---|
| feature | 545 | ~773 (545 + 적 91 + 지형 128 + raid 상태 ~8, §1.4의 1순위 문서) |
| 액션 | 56 | 66 (+raid 10) |
| 타깃 헤드 | 없음 | 64-way + target_mask (1순위 §2) |
| 관측 구조체 | — | `attack_damage`(±vs_air, ±cooldown), `enemy_army_memory` |

작업 시 함께 정리할 기존 부채:

- **헤더 v7 주석 스테일**: ranker_ai_rl_features.h:32-34는 v7이 [534..540]까지라고
  적혀 있으나 실제 코드는 [544]까지 쓴다 (site-blocked 541, explorer-alive 542,
  roamer-alive 543, build-rejected 544). v8 주석 작성 시 바로잡는다.
- Python 쪽 하드코딩 인덱스(augment_rewards의 478/479, imitation의 delta 인덱스들)는
  append-only라 v8에서도 유효하지만, **인덱스 상수를 한 곳(ranker_rl_env.py)에 모으고
  C++ 헤더와 대조하는 회귀 테스트**(feature 버전·카운트·주요 인덱스 몇 개를 JSONL
  헤더로 내보내 검증)를 이번에 추가하는 것을 권장 — 545 vs 544 같은 드리프트 재발 방지.

## 4. 검증

1. 인코더 회귀 (`ai_play_interface_regression`): 타입 슬롯 카운트, 화력 합, 적 군대 기억
   (가시→기억→소거), 지형 채널 값 케이스 추가.
2. damage 필드 확정 실측: 교전 1회 로그의 HP 감소량 vs 정의 테이블 후보 필드 대조.
3. fog-정직 검증: 시야 밖 적 군대 이동이 기억 채널에 반영되지 **않는지** (움직인 뒤에도
   기억은 옛 위치), 가시 확인 시 소거되는지.
4. 같은 시드 byte-identical 재현 (기억은 결정론적 자료구조로 — 순회 순서 고정).
