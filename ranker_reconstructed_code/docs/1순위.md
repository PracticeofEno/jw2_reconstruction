# 1순위 — 액션 공간의 구조적 천장 제거: (a) 다중 부대 그룹, (b) 공격 위치 인자

관련 문서: `AI_PLAY_MICRO_EXECUTOR_DESIGN.md`(그룹 실행기 계약), `AI_PLAY_RL_STRUCTURE.md`(계층 구조),
`2순위.md`(관측 확장 — 같은 v8 계약으로 묶어 재학습 1회로 처리), `3순위.md`(네트워크 구조).

## 0. 왜 이것이 1순위인가

지금까지의 실측 이력에서 **정책(chooser) 학습 개선보다 실행 능력(executor/액션 공간) 개선이
항상 더 큰 점프를 만들었다**:

- 마이크로 실행기 v1 도입: 랜덤 정책 21.8 → 49.7유닛 (내장 AI 55.3 → 50.7).
- 반면 PPO는 같은 실행기 위에서 BC를 3번 연속 넘지 못했다 (chooser는 병목이 아니었다).

현재 병목은 chooser도 executor의 "how"도 아니고, **정책이 표현할 수 있는 전술의 집합 자체**다.
군대가 단일 그룹 하나뿐이고 공격에 위치 인자가 없어서, "본대 방어 + 소부대 견제", "확장 기지
먼저 타격", "협공" 같은 RTS의 기본 전술이 액션 공간에 존재하지 않는다. 학습이 아무리 잘 되어도
이 천장 위로는 못 올라간다.

## 1. (a) 다중 부대 그룹

### 1.1 현황

- `AiMicroGroup`(ranker_ai_micro_executor.h:20-36)은 6개 그룹이지만 실질 전투 그룹은
  `army` **하나**다. `scout/berry_scout/explorer/roamer`는 각 0..1유닛 전용,
  `economy`는 일꾼 전용.
- 모든 부대 액션(`attack_nearest_enemy`, `attack_enemy_base`, `defend_base`, `retreat`,
  `hunt_neutral_monster`, `hold_army`, `patrol_defense`, `search_enemy_base`)이
  `AiMicroSetObjective(state.micro, AiMicroGroup::army, …)` 한 곳을 덮어쓴다
  (ranker_ai_scripted_bot.cpp:892-924). 즉 "전군 공격 ↔ 전군 방어"의 이분법.
- 실행기 자료구조는 사실상 이미 다중 그룹을 지원한다:
  `objectives`는 그룹별 배열(`std::array<AiMicroObjective, kAiMicroGroupCount>`,
  ranker_ai_micro_executor.h:198), `AiMicroAssignGroup`/`AiMicroGroupMembers`/
  `AiMicroGroupCentroid`가 전부 그룹 인자를 받는다. **막힌 곳은 실행기가 아니라
  "정책이 army 외의 전투 그룹을 지정할 방법이 없다"는 액션 계약이다.**

### 1.2 설계 목표

- 정책이 **본대(main)와 별동대(raid)** 두 전투 그룹에 서로 다른 목표를 줄 수 있어야 한다.
- 그룹 편성(누가 어느 그룹인가)은 정책이 유닛 단위로 고르게 하지 않는다 — 유닛 지정은
  flat discrete 액션으로 표현 불가능하고, AlphaStar처럼 포인터 네트워크를 붙이는 것은
  현 단계 과투자다. **편성 규칙은 실행기가 결정론적으로 수행하고, 정책은 "분리/합류/목표"만
  고른다** (기존 "when/what은 정책, how는 실행기" 계약 유지).

### 1.3 액션 설계 (권장안)

`AiMicroGroup`에 `raid = 6` 추가 (`kAiMicroGroupCount = 7`). 역할 기본 배정은 지금처럼
전투원 → `army`(본대). 추가 액션 (append-only, 56 → 66):

| 액션 | 의미 | legal 조건 |
|---|---|---|
| `detach_raid` | 본대에서 별동대 분리. 편성 규칙: 기동성 우선(이속 내림차순, 동률이면 원거리 우선)으로 본대의 **30%** (최소 3, 최대 14 = 1청크) | 본대 전투원 ≥ 6, raid 비어 있음 |
| `merge_raid` | 별동대 전원을 본대로 복귀 (그룹 재배정만; 목표는 본대 것을 따름) | raid 비어 있지 않음 |
| `raid_attack_units` | raid ← attack(units_first) | raid 있음 ∧ (적 가시 ∨ 기억) |
| `raid_attack_base` | raid ← attack(buildings_first) — 위치 인자와 결합 시 §2의 타깃 셀 적용 대상 | raid 있음 ∧ (적 건물 가시 ∨ 기억 ∨ 시작 후보) |
| `raid_defend_base` | raid ← defend(본대와 같은 앵커 규칙) | raid 있음 |
| `raid_retreat` | raid ← retreat (도착 시 defend 전환은 기존 규칙 재사용) | raid 있음 |
| `raid_hunt_neutral` | raid ← attack(neutral_only) | raid 있음 ∧ 중립 가시 |
| `raid_search` | raid ← search (미탐사 시작 후보 스윕) | raid 있음 ∧ 미탐사 후보 존재 |
| (기존 8개 부대 액션) | 의미 불변 — **본대(army)에만** 적용 | 불변 |

설계 근거:

- **액션 복제(×그룹) 대신 raid 전용 액션 추가**: 기존 8개 액션의 의미가 안 바뀌므로
  BC 데이터셋/모방 라벨(`ranker_imitation.py`)이 그대로 유효하고(새 액션은 라벨 불가 →
  RL 전용, 아래 1.6), 마스크 로직도 본대 것을 복사해 그룹만 바꾸면 된다.
- **분리 비율 고정(30%)**: 비율을 액션으로 쪼개면(10/30/50%) 탐색 부담만 는다. 첫 버전은
  상수로 고정하고, 학습이 raid를 실제로 쓰는 것이 확인되면 `detach_raid_large` 하나를
  추가하는 식으로 증분.
- **기동성 우선 편성**: 별동대의 존재 이유(견제/우회/사냥)에 맞는 결정론적 규칙.
  `AiObservedUnit`에 이동 속도가 이미 있다 (v7 관측).

### 1.4 실행기/펌프 변경 범위

- `AiMicroRoleOf` 기반 신규 유닛 기본 배정: 불변 (전투원 → army). raid는 오직
  `detach_raid`로만 채워지고, 전멸 시 자동 소멸(멤버 0 = 그룹 없음), 신규 생산 유닛은
  본대로 간다 — raid가 소모되면 정책이 다시 분리해야 한다 (의도된 비용).
- `AiMicroExecutorStep`: 그룹 순회가 이미 배열 기반이므로 raid는 army와 동일한
  목표 처리 경로를 탄다. 응집(cohesion)·저체력 후퇴·스턱 복구는 유닛 단위라 그대로 동작.
  **주의 1**: 응집은 "자기 그룹 centroid" 기준이어야 한다 — 현재 코드가 army centroid를
  하드코딩한 곳이 있는지 확인 필요 (ranker_ai_micro_executor.cpp:637-655).
  **주의 2**: 방어 버블·후퇴 목적지 등 "nearest base" 계산은 그룹 공용이라 변경 없음.
- 관측/펌프: `AiObservation.army_objective_kind` 채우는 곳(winmain 펌프)에 raid 목표도
  추가 (2순위 문서의 feature 확장과 함께 — raid 카운트/centroid 방향/목표 one-hot/HP비
  약 8개 feature 추가 권장. 정책이 자기 별동대 상태를 볼 수 없으면 merge/재활용 판단이 불가능).

### 1.5 마스크 규칙

- raid 액션 전부: `raid 멤버 > 0` 전제 (detach 제외). 본대 액션은 불변.
- `detach_raid`는 본대가 작을 때 막는다(≥6). 소부대 쪼개기는 자멸 패턴.
- 마스크는 근사이고 검증기가 최종 권위라는 기존 원칙 유지 (ranker_ai_rl_features.h:19).

### 1.6 학습 관점의 리스크와 대응

- **BC 라벨 불가**: 인간/내장 AI 리플레이에서 그룹 분리를 관측으로 복원할 수 없다.
  새 액션 10개는 BC에서 항상 no-label → BC 정책은 raid를 안 쓴다. **RL(자가대전)이
  발견해야 하는 액션**이며, 이것이 정확히 자가대전이 존재하는 이유다. 엔트로피 보너스가
  새 액션의 초기 탐색을 담보한다 (마스크가 열려 있는 한 샘플링됨).
- **credit assignment 악화**: 액션 56→66 + 지연 보상. 대응: 새 액션 도입 직후 몇 세대는
  게이트 판정에 별동대 사용 여부를 진단 로그로만 관찰 (보상 조작은 하지 않는다 —
  war-score가 견제 성공을 이미 Δhostile_lost로 잡는다).
- **요동(8프레임 재선택) 문제와의 결합**: 본대/raid 목표가 매 결정마다 뒤집히면 두 그룹이
  서로 자리만 바꾸는 병리가 가능. 기존 미결인 목표 히스테리시스(같은 목표 재선택 = no-op,
  이미 translator가 `objective_updated`로 부분 처리)를 raid에도 동일 적용.

## 2. (b) 공격 위치 인자 (spatial target)

### 2.1 현황

- 공격은 **전술 3분류뿐**이다: `units_first / buildings_first / neutral_only`
  (`AiMicroAttackTactic`, ranker_ai_micro_executor.h:60-65). WHERE는 실행기가 매 프레임
  재계산한다 (가시 → 기억 건물 → 미탐사 시작 후보 → 스윕).
- `AiMicroObjective`에는 **이미 `target_x/target_y` 필드가 있고** 실행기가 march point로
  사용한다 (ranker_ai_micro_executor.h:77-78). 정책이 이 값을 지정할 통로만 없다.
- point-attack 경로가 만들어졌다가 비활성화된 흔적: `move_army_to`/`nearest_hostile_to`가
  `(void)`로 봉인되어 있다 (ranker_ai_scripted_bot.cpp:941-942).
- 결과: 적 본진과 확장 중 어느 쪽을 칠지, 아군 두 그룹이 어느 방향에서 진입할지를 정책이
  표현할 수 없다. 다중 그룹(§1)을 만들어도 위치 인자가 없으면 두 그룹이 같은 곳으로 간다.

### 2.2 설계 옵션 비교

| 옵션 | 내용 | 평가 |
|---|---|---|
| A. 보조 타깃 헤드 | 정책 네트워크에 8×8=64-way 타깃 셀 헤드 추가. 위치를 받는 액션일 때만 활성 | **권장.** 기존 8×8 그리드 feature([86..469])와 좌표계가 일치. 액션 수 불변. 네트워크/IPC/PPO 변경 필요 |
| B. 액션 복제 | `attack_cell_00..63` 64개 액션 | 액션 폭발(66→130), 마스크·모방·엔트로피 전부 악화. 기각 |
| C. 8방위 액션 | `attack_direction_N/NE/...` 8개 | 저비용 중간안. 그러나 "확장 기지 좌표"같은 절대 위치 표현 불가. A의 폴백으로만 |

### 2.3 권장안 A 상세

**계약** — 위치를 받는 액션(이하 "공간 액션"): `attack_enemy_base`, `raid_attack_base`,
`defend_base`, `raid_defend_base` (+선택적으로 `search_enemy_base`). 나머지 액션은 타깃
헤드 출력을 무시한다.

- **C++ (실행기/translator)**: 공간 액션에 셀 인덱스 c(0..63)가 오면 셀 중심
  `(cx·512+256, cy·512+256)` px를 `objective.target_x/y`에 넣는다. 실행기의 기존 폴백
  체인(가시 건물 → 기억 → …)은 **셀 반경(512px) 안에서 우선 적용**하고, 셀 안에 대상이
  없으면 셀 중심으로 attack-move 후 기존 전역 체인으로 넘어간다. 셀 인덱스 미지정(구버전
  정책/랜덤 정책)이면 현행 동작 그대로 — **하위 호환**.
- **타깃 마스크**: 액션 마스크와 별도로 64비트 셀 마스크를 인코딩에 추가
  (`AiRlStepEncoding`에 `target_mask[64]`). legal = 탐사된 셀 ∨ 적 건물 기억 셀 ∨
  시작 후보 셀. 전부 0이면 공간 액션 자체를 액션 마스크에서 닫는다.
- **IPC 프로토콜** (ranker_ai_ipc.cpp / ranker_ipc_server.py): 요청에 `"tmask"` 추가,
  응답을 `{"action":N,"target":M}`으로 확장. `target` 없으면 -1 (하위 호환 — 기존
  체크포인트/랜덤 정책이 그대로 돈다).
- **Python (3순위 문서의 네트워크 개편과 함께)**: 정책 헤드 2개 —
  `logits_action[66]`, `logits_target[64]`. 샘플링은 순차(액션 → 공간 액션이면 타깃).
  `logprob = logp(a) + [a∈공간액션]·logp(t)`, 엔트로피도 동일 조건부 합.
  PPO 변경은 logprob 계산부와 rollout 레코드(`target`, `target_logprob`)뿐, GAE/클립은 불변.
- **에피소드 JSONL**: 스텝에 `tgt` 필드 추가 (없으면 -1). `ranker_rl_env.py` 로더 대응.

**BC**: 인간 리플레이의 attack-move 패킷에는 좌표가 있으므로 리플레이 모방 로거
(`-AIIMITATE` 패킷 탭)가 **타깃 셀 라벨을 정확히 뽑을 수 있다** — 공격 위치는 새 액션과
달리 모방 가능. `infer_label`은 건드릴 필요 없음 (packet-exact 라벨만).

### 2.4 (a)+(b) 결합 효과

둘을 합치면 최소형 "멀티태스킹" 전술이 완성된다: 본대 defend(자기 기지 셀) + raid
attack_base(적 확장 셀). 이것이 이 문서 전체의 목표 상태다.

## 3. 구현 순서와 검증

1. **실행기**: `raid` 그룹 + 편성/합류 규칙 + centroid 그룹화 확인.
   회귀: `test_ai_micro_executor_*`에 detach/merge/raid-objective 케이스 추가.
2. **translator/마스크**: 신규 10액션 + 공간 액션 셀 처리 + `target_mask`.
   회귀: 마스크 legal 조건, 셀 → target_x/y 변환, 하위 호환(-1) 케이스.
3. **IPC/펌프**: 프로토콜 확장, 랜덤 정책은 legal 셀 중 uniform.
   스모크: `-AIRANDOM` 20000f 완주 + 같은 시드 byte-identical 재현.
4. **Python**: 2-헤드 정책(3순위 문서), JSONL/환경/BC 로더.
5. **실측 게이트** (변경 채택 기준):
   - 랜덤 정책 A/B (구 exe vs 신 exe, 시드 6개, 20000f): 신규 액션이 실행 실패 없이
     돌아가는지 (plan-failure 로그 0 근접).
   - BC 재수집·재학습 후 리그: 신 계약 BC vs 구 계약 BC 챔피언 — 최소 동급 확인.
   - 자가대전 N세대 후 raid 액션 사용률 > 0 및 게이트 승격 발생 여부.

## 4. 비용

- 체크포인트 전면 무효 (액션 66 + 타깃 헤드). **2순위(관측 v8)·3순위(네트워크)와 반드시
  한 번에 묶어서** 재학습 사이클을 1회로 만든다.
- C++ 변경 규모: 실행기 소(그룹 1개 추가), translator/마스크 중, IPC 소.
  Python 변경 규모: PPO logprob/rollout 중, 서버/환경 소.
