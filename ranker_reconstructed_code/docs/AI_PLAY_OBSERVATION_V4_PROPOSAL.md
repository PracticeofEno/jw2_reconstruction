## 1. 검토 결론 (요약)

현재 관측(v3, 80피처)은 **경제·생산·테크 매크로 학습에는 충분**하다.
그러나 라운드 10 환경이 요구하는 학습 목표 — *건물 섬멸 기반 승패, 워스코어
보상, 셀프플레이 미러전* — 에 대해서는 다음 3가지 핵심 결손이 있다:

1. **안개 너머 적 정보가 정책에 전혀 없다.** 적 관련 피처(31~35)는 현재
   시야 한정. 터틀링 미러전에서는 게임 대부분 동안 전부 0이라, 정책은
   "적이 없는 게임"과 구별하지 못한다. 실행기에는 이미
   `remembered_enemy_buildings[24]` 기억이 있으나 인코더에 노출되지 않는다.
2. **적 "질(가치)" 정보가 없다.** 보상 v3는 유닛 비용 가치 기반인데 관측은
   마소스(100)와 티라노스(5000)를 같은 1로 센다. 교전 승산을 추정할 근거가
   없어 `attack_*` 계열 행동의 가치 학습이 어렵다.
3. **"건물 = 생명" 신호가 없다.** 승패가 건물 보유 기준으로 바뀌었는데
   건물 HP 집계·피격 신호가 관측에 없다 (`army_health`는 기동유닛만 합산).

이를 해결하는 **+20피처 (80 → 100, append-only)** 를 §4에 상세 설계한다.
전부 관측 가능 정보(직접 시야 + 본 것의 기억)만 사용하므로 "정정당당한"
셀프플레이 관측 원칙을 유지한다.

## 2. 현재 관측 파이프라인 구조

```
게임 상태 (g_runtime)
  │
  ▼
build_default_ai_play_observation(state, owner, explored, visible, out)
  │    ranker_winmain.cpp — 소유 유닛 + 시야 확인된 적 유닛 + 타일 안개 투영
  ▼
AiObservation                      (ranker_ai_observation.h)
  │    유닛 리스트, 타일 리스트, 자원/인구, 연구 레벨, 시작 위치, 종족 등
  ▼
EncodeAiObservationForRl(obs)      (ranker_ai_rl_features.cpp)
  │    순수 결정론 함수 — 같은 관측 → 바이트 동일 출력
  ▼
AiRlStepEncoding { features[80], legal_mask[41] }
  │
  ├─► 온라인: -AIIPC로 Python 정책 서버에 전송 {"t":"act","feat":[...],"mask":[...]}
  └─► 오프라인: ai_rl_episode.jsonl 스텝 레코드 {feat, mask, a, r, ...}
```

**시야 규칙 (AiObservation의 정보 은닉) — 2026-08-29 안개 정직성 전면
수정 반영:**
- 소유 유닛: 항상 전부 관측 (명령 상태·큐·목적지 포함).
- **활성 시야 레이어**: 엔진은 현재-시야(current) 그리드를 로컬 관전
  플레이어에 대해서만 유지한다 (AI 오너의 행은 항상 비어 있음 —
  프로브로 실증). 따라서 관측 빌더가 매 결정마다 엔진의 유닛별 시야
  전개(`ApplyActiveUnitVisibility`, 반경 + 지형 차폐 동일)를 **스크래치
  그리드**에 재생해 관측 오너의 활성 시야를 직접 계산한다
  (`g_runtime.ai_play_vision_scratch`; 실제 그리드는 불변 — 심/리플레이
  무영향). 트릭: 오너별 shift 비트는 특수 유닛 전용이므로, 스크래치
  컨텍스트의 local_player_slot을 관측 오너로 지정해 로컬 마스크
  (`kGameplayVisibilityVisible`) 경로로 기록시킨다.
- 적 유닛: `default_ai_play_unit_active_visible` — 위 활성 시야 스크래치에
  대한 엔진 타깃 시야 판정. **수정 전에는 실제 그리드의 탐사(owner)
  레이어 기반이라 "탐사한 땅 위의 적은 영구히 보이는" 월핵이었다.**
  사적 정보(목적지, 생산 큐, 타깃)는 여전히 비공개.
- 타일 `visible`: 활성 시야 스크래치에서 채움 (수정 전에는 AI 오너에서
  항상 false — 실행기의 철거-확인 기억 로직이 죽은 코드였음; 이제 동작).
- `resource_amount`: **마지막으로 본 값 스냅샷** (오너별
  `ai_play_resource_memory`; 활성 시야 안에서만 라이브 갱신, 탐사만 된
  타일은 기억값, 미탐사·미목격은 0). 수정 전에는 탐사 타일의 라이브
  값이 안개를 뚫고 새어 들어왔다. 유닛이 다시 밝히면 자동 교정.
- 시작 위치 (2026-08-29 익명화): **맵의 시작 후보 좌표 목록만** 공개
  (`start_candidate_x/y[8]` + `start_candidate_mask`, 맵슬롯 순서·익명,
  4인용 맵이면 4개; 자기 시작점은 `start_x/y`와 좌표 비교로 식별).
  상대가 어느 후보를 점유했는지는 비공개 — 정찰로 알아내야 한다.
  실행기 행군/정찰은 기존의 "미탐사 후보 우선, 탐사-빈 후보 스킵" 체인
  그대로 후보를 순회하며, 피처 77은 "가장 가까운 비자기 후보까지
  거리"로 재해석됨. (이전 구현은 셔플 배정 결과인 오너별 진짜 시작
  좌표를 노출했음 — 위반이라 제거; 워스코어 손실 집계는 보상 전용
  특권 경로라 스타트업 슬롯에서 직접 경쟁자를 식별하도록 분리.)

> 이 수정으로 그룹 A(기억된 적 정보)의 가치가 더 커졌다: 이제 적
> 유닛/건물은 활성 시야에서만 보이므로, 안개 너머 정보는 온전히 기억
> 피처의 몫이다. 또한 기존 BC/모방 데이터셋과 체크포인트는 월핵
> 의미론에서 수집·학습된 것이므로 다음 라운드 전 재수집이 필요하다.

## 4. 결손 분석 및 제안 피처 상세 (v4: +20, 80 → 100)

각 피처마다 **원천 데이터 → 인코딩 → 상황별 예시값** 을 명시한다.
스케일은 제안값이며 구현 시 실측 분포로 조정 가능. 모든 신규 피처는
append-only (기존 인덱스 불변).

### 그룹 A — 기억된 적 정보 (안개 너머) [80..82]

> **해결하는 결손**: 미러전에서 적 피처가 거의 항상 0 → 정책이 상대를
> 사실상 못 본다. 공격/방어 *타이밍* 학습이 불가능.

#### [80] remembered_enemy_building_count — 기억된 적 건물 수

- **원천**: 실행기 `TyranoScriptedBotState.remembered_enemy_buildings[24]`
  (한 번이라도 시야에 들어온 적 건물; 해당 타일이 보이는데 건물이 없으면
  철거 확인으로 제거 — 이미 구현·검증됨, mop-up sweep에서 도입).
- **인코딩**: `norm(count, 20)`.
- **구현 포인트**: 인코더는 순수 함수를 유지해야 하므로, 실행기 기억을
  `AiObservation`에 복사해 넣는 필드 추가
  (`remembered_enemy_buildings` 카운트 + 최근접 좌표) 후 인코딩.

| 상황 | 원시값 | 피처값 |
|------|--------|--------|
| 게임 초반, 정찰 전 | 0 | 0.00 |
| 정찰로 적 본진 확인 (네스트1+인구3+에그1) | 5 | 0.25 |
| 장기전, 적 기지 2곳 파악 | 14 | 0.70 |
| 적 건물 전부 철거 확인 (승리 직전) | 0 | 0.00 |

#### [81] nearest_remembered_building_distance — 최근접 기억 건물 거리

- **원천**: 내 시작점(`obs.start_x/y`) 기준 기억 건물 최근접 거리.
- **인코딩**: `min(픽셀거리/32/128, 1)` (타일 단위, 맵 대각 ~128타일 기준).
  기억 없음 → **센티널 1.0** (피처 [80]=0과 조합해 구분).

| 상황 | 원시값 | 피처값 |
|------|--------|--------|
| 기억된 건물 없음 | — | 1.00 |
| 적 전진 건물 40타일 | 40타일 | 0.31 |
| 적 본진 90타일 | 90타일 | 0.70 |

#### [82] frames_since_enemy_seen — 적 최종 목격 후 경과 시간

- **원천**: 실행기 상태에 신규 필드 `last_enemy_seen_frame` (적 유닛/건물이
  시야에 있던 마지막 프레임; 매 관측 갱신). 현재프레임 − 그 값.
- **인코딩**: `norm(경과, 6000)` (6000프레임 ≈ 결정 750회 ≈ 충분히 "옛날").
  한 번도 못 봤으면 센티널 1.0.

| 상황 | 원시값 | 피처값 |
|------|--------|--------|
| 지금 교전 중 (적이 시야에 있음) | 0 | 0.00 |
| 1200프레임 전 정찰꾼이 적 군 목격 | 1200 | 0.20 |
| 개전 후 한 번도 적을 못 봄 | ∞ | 1.00 |

**학습 효과**: "0.9 이상 = 오랫동안 깜깜함 → 정찰 가치 상승"을 정책이
직접 학습 가능. [85](기억 적군 가치)와 조합하면 정보의 신선도를 안다.

### 그룹 B — 가치 가중 전력 [83..91]

> **해결하는 결손**: 워스코어 보상(가치 기반)과 관측(수 기반)의 불일치.
> 교전 승산 추정 근거 부재. 상대 종족 미인지.

#### [83] own_army_value — 자군 전투유닛 가치 합

- **원천**: 완성 전투유닛(기동, 일꾼 제외)의 감사 비용 합.
  비용표는 인코더에 이미 있는 `kUnit*Cost` 상수 재사용
  (ai_techtree_audit.txt 검증본).
- **인코딩**: `norm(Σcost, 20000)`.

| 상황 | 원시값 | 피처값 |
|------|--------|--------|
| 마소스 10기 (100×10) | 1,000 | 0.05 |
| 마소스10+벨로시스4+트리세스2 | 3,600 | 0.18 |
| 티라노스 1 + 대군 | 14,000 | 0.70 |

기존 [29](own_army/50)는 첫째·셋째를 비슷하게 취급 — 이 피처는 14배 차이로
구분한다. 보상 v3의 `army_value`(econ 항)와 동일 정의라 가치망이 보상을
직접 볼 수 있게 된다.

#### [84] visible_enemy_army_value — 보이는 적군 가치 합

- **원천**: 현재 시야 내 적 기동유닛의 타입별 비용 합. **전 종족 비용표
  필요** — ai_techtree_audit.txt에 이미 4종족 전체 로스터·비용이 덤프되어
  있으므로 인코더에 종족 대칭 비용 테이블(타입ID→비용)로 옮긴다.
- **인코딩**: `norm(Σcost, 20000)`.

| 상황 | 원시값 | 피처값 |
|------|--------|--------|
| 적 안 보임 | 0 | 0.00 |
| 적 마소스 8기 접근 | 800 | 0.04 |
| 적 주력 (벨로시스 20) 목격 | 5,000 | 0.25 |

**[83] vs [84] 비교 = 교전 승산 추정** — `attack_nearest_enemy` /
`retreat` 선택의 직접 근거.

#### [85] last_seen_enemy_army_value — 기억된 적군 가치

- **원천**: 실행기 상태 신규 필드. 시야에 적군이 있을 때마다
  `max(현재 관측 가치, 기존값)` 또는 최근 관측값으로 갱신 (제안: 최근
  관측 스냅샷 + 목격 프레임; 갱신 정책은 구현 시 결정). 시야가 끊겨도 유지.
- **인코딩**: `norm(값, 20000)`.

| 상황 | [84] | [85] | [82] |
|------|------|------|------|
| 3000프레임 전 5,000가치 군 목격, 지금 안 보임 | 0.00 | 0.25 | 0.50 |
| 방금 그 군과 조우 | 0.25 | 0.25 | 0.00 |

#### [86] visible_enemy_air_count — 보이는 적 공중유닛 수

- **원천**: 시야 내 적 중 공중 타입. 공중 판별은 타입 테이블
  (`UnitMovementDefinition` 이동 클래스) 또는 종족 대칭 타입ID 블록.
- **인코딩**: `norm(count, 20)`.
- **예시**: 적 프테라스류 5기 → 0.25. (대공 유닛/업그레이드 준비 판단)

#### [87] visible_enemy_worker_count — 보이는 적 일꾼 수

- **원천**: 시야 내 적 일꾼 (종족별 일꾼 타입 = tribe×0x10).
- **인코딩**: `norm(count, 50)`.
- **예시**: 적 본진 정찰로 일꾼 12 확인 → 0.24. (상대 경제 규모 읽기;
  일꾼 사냥 가치 판단)

#### [88..91] enemy_tribe_one_hot — 상대 종족 원-핫 (4)

- **원천**: 로비 슬롯 종족 (공개 정보; `mirror_owner_slots` 경유).
  1v1 기준 "나 아닌 경쟁자"의 종족. 다수 적이면 최근접 시작점 소유자 기준.
- **인코딩**: 원시(0)/엘프(1)/티라노(2)/데몬(3) 원-핫.

| 상황 | 피처값 |
|------|--------|
| -AITRIBE 데몬 빌트인 상대 | [0, 0, 0, 1] |
| -AIVS 티라노 미러 | [0, 0, 1, 0] |

### 그룹 C — 건물 생존·손실 (섬멸 룰의 체력바) [92..95]

> **해결하는 결손**: 승패 판정이 건물 기준인데 건물 생존 신호 부재.
> 보상(워스코어)의 손실 항을 가치망이 관측으로 예측 불가.

#### [92] own_building_hp_ratio — 자군 건물 HP 비율

- **원천**: 완성 건물들의 `Σhealth / Σmax_health` (관측 유닛 리스트에서
  집계 — 인코더 수정만으로 가능, 관측 구조 변경 불요).
- **인코딩**: 비율 그대로 [0,1]. 건물 없으면 0.0 (= 섬멸 상태와 일치).

| 상황 | 원시값 | 피처값 |
|------|--------|--------|
| 무피해 | 8000/8000 | 1.00 |
| 본진 반파 + 인구네스트 빈사 | 6200/8000 | 0.78 |
| 마지막 건물 빈사 (패배 직전) | 300/2000 | 0.15 |

#### [93] buildings_under_attack — 피격 중 건물 수

- **원천**: 실행기 상태에 직전 결정 사이클의 자군 건물 HP 스냅샷
  (id→health 맵) 유지, 이번 사이클에 HP가 감소한 건물 수.
- **인코딩**: `norm(count, 10)`.

| 상황 | 원시값 | 피처값 |
|------|--------|--------|
| 평시 | 0 | 0.00 |
| 적 드랍이 인구네스트 2채 타격 중 | 2 | 0.20 |

기존 [76](raid_enemies)은 "적이 근처에 있다", 이것은 "실제로 부서지고
있다" — 방어 긴급도의 질적 차이.

#### [94] own_value_lost — 자군 누적 손실 가치

- **원천**: **이미 존재하는** `g_runtime.ai_play_unit_value_lost[own] +
  ai_play_building_value_lost[own]` (보상 v3용 사망 계정). 내 유닛의 죽음은
  본인이 항상 관측 가능하므로 특권 정보가 아니다 → 피처로 승격 정당.
- **인코딩**: `norm(값, 20000)`.

| 상황 | 원시값 | 피처값 |
|------|--------|--------|
| 무손실 | 0 | 0.00 |
| 마소스6 + 일꾼2 잃음 | 800 | 0.04 |
| 본진 트레이드 대패 | 7,400 | 0.37 |

#### [95] witnessed_enemy_value_destroyed — 목격한 적 손실 가치

- **원천**: 신규 계정 필요. 사망 싱크(`on_death_accounted`,
  ranker_unit_lifecycle.cpp)에서 죽는 유닛이 **해당 owner의 시야 안**일 때
  per-observer 누적 (내가 죽인 것 + 목격한 것 = 관측 가능 정보).
  주의: 기존 `ovl/obl`(전체 적 손실)은 특권 정보이므로 보상 전용 유지 —
  피처는 반드시 목격분만.
- **인코딩**: `norm(값, 20000)`.
- **예시**: 방어전에서 적 마소스 15기 격퇴 → 1,500 → 0.075.

**[94]·[95] 조합 = 워스코어 보상의 관측 가능 버전** — 가치망의 보상 예측
분산을 크게 줄인다.

### 그룹 D — 방향 [96..97]

> **해결하는 결손**: 최근접 적 *거리*(34)만 있고 방위가 없음.

#### [96, 97] enemy_direction_dx, dy — 적 중심 방향

- **원천**: 보이는 적 위치 중심 (없으면 기억 건물 중심, 그것도 없으면
  미지) − 내 시작점. 단위벡터화.
- **인코딩**: `(d + 1) / 2` 로 [−1,1]→[0,1] 매핑. 미지면 (0.5, 0.5).

| 상황 | 원시 방향 | 피처값 |
|------|-----------|--------|
| 적 위치 전혀 모름 | — | (0.50, 0.50) |
| 적이 정동쪽 | (+1, 0) | (1.00, 0.50) |
| 적이 북동쪽 | (+0.7, −0.7) | (0.85, 0.15) |

경로·타게팅은 실행기 담당이므로 세밀한 공간 정보는 불필요 — "전선이
어느 쪽인가" 수준의 저비용 신호.

### 그룹 E — 진행/맥락 [98..99]

#### [98] explored_fraction — 맵 탐사율

- **원천**: `obs.tiles`의 explored 비율 (인코더에서 집계 가능; 성능상
  관측 빌더에서 카운트해 넘기는 편이 나음 — 타일 벡터는 이미 순회함).
- **인코딩**: 비율 [0,1].
- **예시**: 초반 본진 주변만 0.09 → 정찰 후 0.34 → 장기전 0.87.
- **학습 효과**: `scout_map`의 한계효용(다 밝힌 맵에서 정찰 무가치)을
  학습 가능하게 함.

#### [99] competitors_remaining — 남은 경쟁자 수

- **원천**: 건물을 보유한 경쟁자 수. 단, 상대 건물 보유 여부는 특권일 수
  있으므로 **관측 가능 버전** = `competitor_start_mask` 인구수에서 "철거
  확인된 시작점" 제외 (기억 건물 + 탐사 정보 기반). 초기 구현은 단순히
  `popcount(competitor_start_mask)`로 시작해도 무방 (1v1 고정값).
- **인코딩**: `norm(count, 3)`.
- **예시**: 1v1 → 항상 0.33. FFA 3자 중 1 탈락 → 0.67→0.33.

## 5. 신규 인프라 요구 정리

| 항목 | 위치 | 규모 |
|------|------|------|
| 기억 건물 카운트/최근접 → 관측 복사 | AiObservation 필드 추가 + winmain 빌더 | 소 |
| last_enemy_seen_frame / last_seen_army_value | TyranoScriptedBotState (실행기 상태) | 소 |
| 건물 HP 스냅샷 (id→hp) | TyranoScriptedBotState | 소 |
| 전 종족 타입ID→비용 테이블 | 인코더 상수 (audit 덤프 전사) | 중 (표 전사) |
| 목격 적 손실 계정 (per-observer) | on_death_accounted에 시야 체크 추가 | 중 (시야 판정 접근 필요) |
| 탐사 타일 카운트 | 관측 빌더 | 소 |
| 상대 종족 노출 | AiObservation 필드 + 빌더 | 소 |

인코더 자체는 순수 함수 유지 — 모든 기억/계정은 관측 빌드 입력으로
주입한다 (결정론·테스트 가능성 보존; 같은 관측 → 바이트 동일 인코딩).

## 6. 마이그레이션 계획

1. **체크포인트 무효화**: 80→100은 레이어 셰이프 변경 → 모든 v3(80×41)
   체크포인트 무효. `ranker_ppo.py`는 이미 n_features/n_actions 불일치 시
   하드 에러 — 안전망 확인됨.
2. **적용 시점**: 기존 관행대로 **라운드 경계에서만** (환경/관측을 라운드
   중간에 바꾸면 게이트가 왜곡됨). 현재 진행 중인 라운드 10을 중단하지
   말고, 다음 재시작 시점에 배치.
3. **Python 동기화**: `ranker_rl_env.py` N_FEATURES=100,
   `ranker_imitation.py` 라벨러는 변경 불요 (라벨은 카운트 델타 기반),
   BC 데이터셋 재수집 (`-AIIMITATE`, -AITRIBE:4, 신규 exe).
4. **버전 태깅**: `kAiRlFeatureVersion = 4`, episode JSONL에 피처 버전
   기록 검토 (현재 없음 — 이참에 `fv:4` 필드 추가 권장; 구버전 데이터
   혼입 방지).
5. **회귀 테스트**: `ai_play_interface_regression`에 신규 피처 케이스 추가
   (기억 건물 인코딩, 가치 합산, HP 비율, 방향 매핑, 센티널 값들).
6. **검증 순서**: 회귀 통과 → -AIRANDOM 단판 재현성(동일 시드 바이트 동일)
   → BC 재수집/재학습 → 다음 셀프플레이 라운드 시작.

## 7. 이번 제안에서 제외한 것 (후순위 레버)

- **공간 피처맵 (미니맵 플레인, AlphaStar식)**: 현 병목(교전 판단) 대비
  비용 과대. MLP→CNN 전환 필요. 스칼라 확장으로 정체 시 재검토.
- **Recurrent actor / 추세 피처**: 설계 문서의 보류 항목과 동일. [82],
  [93], [94/95]가 저렴한 부분 대체재.
- **Centralized critic (특권 가치망)**: 아키텍처 옵션으로 유효 — episode
  JSONL이 이미 특권 손실(`vl/bl/ovl/obl`)을 나르므로 확장 비용 낮음.
  관측 확장과 독립적으로 도입 가능.
- **적 개별 유닛 슬롯 (top-K 리스트)**: 가치 합산으로 우선 충분.

## 부록 B — 실제 스텝 데이터 예시 (episode JSONL)

교전 직전 상황의 한 스텝, 신규 구간 [80..99]만 주석 표시:

```json
{"owner":1, "f":18400, "a":12, "feat":[ /* ...기존 80개... */,
  0.25, 0.70, 0.05,             /* A: 기억건물 5, 90타일, 300프레임 전 목격 */
  0.18, 0.04, 0.25, 0.0, 0.24,  /* B: 내군 3600 vs 보임 800, 기억 5000,
                                       공중 0, 적 일꾼 12 */
  0.0, 0.0, 1.0, 0.0,           /* B: 상대 티라노 (미러) */
  0.78, 0.20, 0.04, 0.075,      /* C: 건물HP 78%, 2채 피격중,
                                       손실 800, 격파 1500 */
  0.85, 0.15,                   /* D: 적은 북동쪽 */
  0.34, 0.33 ],                 /* E: 탐사 34%, 경쟁자 1 */
 "mask":[ /* 41개, 변경 없음 */ ]}
```

읽는 법: 이 상태는 "적 본진 위치를 알고(0.25/0.70), 정보가 신선하며(0.05),
내 군이 보이는 적보다 4.5배 강하지만 기억상 본대는 대등(0.18 vs 0.25),
내 건물이 두 채 맞고 있는(0.20)" 상황 — 정책이 방어 후 반격 판단을 내릴
수 있는 근거가 전부 관측에 있다.
